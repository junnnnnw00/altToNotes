## Slide 2

### Dictionary

**핵심 개념**:
Dictionary는 `(key, info)` 쌍의 집합으로 이루어진 추상 자료형(Abstract Data Type, ADT)입니다. 각 키(`key`)는 집합 내에서 한 번만 등장해야 하며 (즉, 고유한 ID를 가짐), 각 키에는 단일 정보(`info`) 항목이 연결됩니다.

**구체적 예시**:
학생 ID를 `key`로, 학생의 성적이나 연락처를 `info`로 저장하는 경우를 생각할 수 있습니다. 각 학생 ID는 고유해야 합니다.

**강의 맥락**:
교수님께서는 Dictionary가 `key`와 `information`을 가지는 자료형이라고 설명하며, 이전에 봤던 다른 자료구조들과 유사하다고 언급하셨습니다. 가장 중요한 제약 조건은 "각 키는 집합 내에서 단 한 번만 나타난다"는 것으로, 이는 고유 ID(`unique ID`)의 개념과 일치합니다. 즉, 각 키에는 하나의 항목만 연결됩니다. Dictionary는 종종 추상 자료형(ADT)이라고 불리는데, 이는 여기에 저장되는 정보(`info`)가 임의로 정의될 수 있기 때문입니다.

**시험 포인트**:
* ⭐ Dictionary의 정의: `(key, info)` 쌍의 집합이자 ADT라는 점을 이해해야 합니다.
* ⭐ Dictionary의 핵심 제약 사항: 모든 `key`는 고유해야 한다는 점 (`unique ID`).
* ⭐ Dictionary의 세 가지 기본 연산: 삽입(`Insert`), 삭제(`Delete`), 탐색(`Search`)이 무엇인지 명확히 알아야 합니다.

**코드/수식 해설**:
*   `x = (key, info)`: Dictionary에 저장되는 하나의 데이터 항목 `x`는 `key`와 그에 해당하는 `info`로 구성됩니다.
*   `Insert(x, D)`: `x` (`key`와 `info`를 포함하는 항목)를 Dictionary `D`에 저장하는 연산입니다.
*   `Delete(k, D)`: 특정 `key` `k`에 해당하는 항목 `x = (k, info)`를 Dictionary `D`에서 제거하는 연산입니다.
*   `Search(k, D)`: 특정 `key` `k`에 해당하는 항목 `x = (k, info)`를 Dictionary `D`에서 찾아 그 `info`를 반환하는 연산입니다.

## Slide 3

## Dictionary Implementations

### 핵심 개념
*   **Dictionary (사전)**: `key`와 `information` 쌍으로 데이터를 저장하는 자료형입니다. 각 `key`는 집합 내에서 한 번만 나타나야 하는 제약 조건이 있습니다.
*   **기본 연산**: `Insert` (데이터 삽입), `Delete` (데이터 삭제), `Search` (데이터 탐색) 세 가지가 핵심입니다.
*   **탐색 문제(Search Problem) 해결 접근법**:
    1.  **순차적 방법 (Sequential methods)**: `Unsorted list` (정렬되지 않은 리스트)나 `Sorted list` (정렬된 리스트)를 활용합니다.
    2.  **해싱 방법 (Hashing method)**: `key` 값을 통해 데이터에 직접 접근하여 처리합니다.
    3.  **트리 인덱싱 방법 (Tree indexing methods)**: `Binary Search Tree` (이진 탐색 트리), `Balanced Search Trees` (균형 탐색 트리, 예: AVL, 2-3 트리) 등을 활용합니다.

### 코드/수식 해설
주요 Dictionary 구현 방법들의 시간 복잡도 (최악의 경우, 평균)는 다음과 같습니다.
| Data Structure         | Worst               | Average             |
| :--------------------- | :------------------ | :------------------ |
| Unsorted list          | $O(n)$              | $O(n)$              |
| Sorted list            | $O(\log n)$         | $O(\log n)$         |
| Hash Table             | $O(n)$              | $O(1)$              |
| Binary Search Tree     | $O(n)$              | $O(\log n)$         |
| Balanced Search Trees  | $O(\log n)$         | $O(\log n)$         |
| (AVL, 2-3)             |                     |                     |

*   **`Unsorted list`**: 검색, 삽입, 삭제 모두 특정 항목을 찾기 위해 모든 요소를 순차적으로 확인해야 하므로 $O(n)$ 시간이 소요됩니다.
*   **`Sorted list`**: 이진 탐색(binary search)과 유사하게 탐색 범위를 절반으로 줄여나가므로 $O(\log n)$ 시간이 소요됩니다. (단, 삽입/삭제 시에는 요소 이동 때문에 $O(n)$이 될 수 있습니다.)
*   **`Hash Table`**: `key`를 해시 함수에 넣어 해당 위치로 직접 접근하므로, 충돌이 없는 이상 평균적으로 $O(1)$의 상수 시간 복잡도를 가집니다. 하지만 최악의 경우 (모든 `key`가 같은 해시 값으로 매핑되는 등) $O(n)$이 될 수 있습니다.
*   **`Binary Search Tree`**: 균형 잡힌 경우 평균 $O(\log n)$이지만, 데이터 삽입 순서에 따라 트리가 한쪽으로 기울어질(skewed) 경우 최악 $O(n)$이 될 수 있습니다.
*   **`Balanced Search Trees` (AVL, 2-3)**: 트리의 균형을 항상 유지하여 최악의 경우에도 $O(\log n)$ 시간 복잡도를 보장합니다.

### 구체적 예시
*   `Unsorted list`에서 `Search` 연산을 수행할 경우, 원하는 항목을 찾기 위해 리스트의 첫 번째 요소부터 마지막 요소까지 순차적으로 비교해야 합니다.
*   `Sorted list`에서 `Search` 연산은 `key`를 기준으로 `binary search`를 수행하여 탐색 범위를 반복적으로 절반씩 줄여나가 목표 `key`를 찾습니다.
*   `Hash Table`은 `key`를 해시 함수에 입력하면 해당 `key`가 저장된 `hash table` 내의 특정 `slot` 인덱스를 즉시 반환하여 데이터에 빠르게 접근할 수 있습니다.

### 강의 맥락
교수님은 Dictionary가 `key`와 `information`으로 구성되며, 각 `key`가 유일하다는 점을 강조합니다. `Insert`, `Delete`, `Search`가 Dictionary의 세 가지 핵심 연산이라고 설명하며, Dictionary를 구현하는 여러 방법들을 나열합니다. 특히 `Hash Table`의 경우 평균 시간 복잡도가 $O(1)$이라는 점을 "마법 같다(magic)"고 표현하며 그 장점을 크게 강조합니다. 동시에 `Hash Table`의 최악의 경우 시간 복잡도가 $O(n)$이 될 수 있으며, 이는 `Binary Search Tree`가 `skewed` (한쪽으로 치우친) 형태가 될 때의 최악의 경우와 유사하다고 설명합니다.

### 시험 포인트
*   ⭐**Dictionary의 정의**: `key`와 `information` 쌍, `key`의 유일성.
*   ⭐**Dictionary의 3대 기본 연산**: `Insert`, `Delete`, `Search`.
*   ⭐**`Hash Table`의 시간 복잡도**: **평균 $O(1)$** (핵심!)과 최악 $O(n)$의 의미를 정확히 이해해야 합니다.
*   ⭐**`Binary Search Tree`의 Worst-case $O(n)$**: 트리가 `skewed` 될 때 발생함을 이해해야 합니다.
*   ⭐**`Balanced Search Trees`의 장점**: 최악의 경우에도 $O(\log n)$을 보장하는 이유를 알아두세요.

## Slide 4

### 핵심 개념
*   **Bucket Sort (버킷 정렬)**: 키 값을 기반으로 데이터를 여러 버킷에 분산시킨 후, 각 버킷을 정렬하고 최종적으로 모든 버킷의 내용을 순서대로 합쳐 정렬하는 **비비교(Non-comparison)** 정렬 알고리즘입니다. 해싱(Hashing)과 유사한 아이디어를 가집니다.
*   **두 단계 과정**:
    *   **Phase 1: Scattering (분산)**: 입력 `(key, info)` 쌍들을 해당 키 값에 따라 적절한 버킷에 나누어 넣습니다. 만약 하나의 버킷에 여러 항목이 들어간다면, 해당 버킷 내에서 별도의 정렬 알고리즘(예: 삽입 정렬)을 사용하여 정렬할 수 있습니다.
    *   **Phase 2: Gathering (수집)**: 버킷들을 순서대로(예: 0번 버킷부터 마지막 버킷까지) 방문하며 각 버킷의 내용을 원래의 리스트로 수집하여 최종 정렬된 리스트를 완성합니다.

### 구체적 예시
슬라이드에 제시된 `(key, info)` 쌍 리스트: `7,d`, `1,c`, `3,a`, `7,g`, `3,b`, `7,e`

1.  **Scattering**:
    *   키가 `1`인 `1,c`는 1번 버킷으로.
    *   키가 `3`인 `3,a`, `3,b`는 3번 버킷으로.
    *   키가 `7`인 `7,d`, `7,g`, `7,e`는 7번 버킷으로.
    (나머지 버킷은 비어있다고 가정)

2.  **Gathering**:
    *   1번 버킷에서 `1,c`를 가져옵니다.
    *   3번 버킷에서 `3,a`, `3,b`를 가져옵니다.
    *   7번 버킷에서 `7,d`, `7,g`, `7,e`를 가져옵니다.
    *   결과적으로 정렬된 리스트: `1,c`, `3,a`, `3,b`, `7,d`, `7,g`, `7,e`

### 강의 맥락
교수님은 Bucket Sort를 **해싱(hashing)과 매우 유사한 아이디어**를 가진 "매우 영리한(very clever) 아이디어"라고 설명하며, 해싱 개념을 도입하기 위한 복습 자료로 사용했습니다.

*   "우리는 이전에 버킷 정렬(bucket sort)과 비슷한 것을 보았습니다. 이것 또한 매우 영리한 아이디어였고, 그 아이디어는 사실 해싱과 매우 유사합니다."
*   "버킷 정렬은 우리가 공부했던 **비교 정렬이 아닌(non-comparison sort)** 알고리즘입니다."
*   "아이디어는 정말 간단했습니다. `(key, information)` 쌍이 있을 때, 키가 $0$부터 $N-1$까지의 특정 정수 범위 내에 있다고 가정합니다. 그리고 버킷을 만든 다음, 키에 따라 모든 항목을 **분산(scatter)**시킵니다."
*   "일단 분산되면, 우리는 왼쪽에서 오른쪽으로 모든 항목을 **수집(gather)**합니다."
*   "이때 시간 복잡도는 $O(n + N)$이 됩니다. 여기서 $N$은 버킷의 수이고, $n$은 요소의 수입니다. 이는 다른 퀵정렬이나 병합정렬 등이 평균적으로 $O(n \log n)$인 것과 비교했을 때 큰 차이였습니다. 그래서 기본적으로 $O(n)$이 됩니다."
*   "해싱도 이와 유사합니다." 라고 언급하며 다음 해싱 내용으로 넘어갔습니다.

### 시험 포인트
*   ⭐ **Bucket Sort는 비비교 정렬(Non-comparison sort)이다.** 이는 다른 비교 정렬(Quick Sort, Merge Sort 등)과 차별화되는 중요한 특징입니다.
*   ⭐ Bucket Sort의 핵심적인 두 단계는 **Scattering (분산)**과 **Gathering (수집)**이다.
*   ⭐ Bucket Sort의 시간 복잡도는 $O(n+N)$이다 (여기서 $n$은 항목의 수, $N$은 버킷의 수).
*   ⭐ Bucket Sort는 해싱(Hashing)과 그 기본적인 작동 원리에서 아이디어를 공유하며 유사점이 많다.

## Slide 5

## Review: Bucket Sort

### 핵심 개념
버킷 정렬(Bucket Sort)은 비교 정렬(non-comparison sort)의 일종으로, 데이터를 정렬된 순서대로 여러 개의 '버킷(bucket)'에 분산시킨 후 각 버킷의 내용을 순서대로 모으는 방식입니다. 특히 키 값이 특정 범위 내에 고르게 분포할 때 매우 효율적입니다.

### 구체적 예시
주어진 아이템 `7d, 1c, 3a, 7g, 3b, 7e`를 정렬하는 과정:
1.  **Phase 1: Scattering into buckets**
    *   키(숫자)를 기반으로 해당 버킷에 아이템을 분산합니다.
    *   `1c`는 버킷 1에, `3a`와 `3b`는 버킷 3에, `7d`, `7g`, `7e`는 버킷 7에 들어갑니다.
    *   각 버킷 내에서는 아이템들이 체인 형태로 연결될 수 있습니다. (예: `3a` 다음에 `3b`)
2.  **Phase 2: Gathering**
    *   버킷 0부터 시작하여 각 버킷의 아이템들을 순서대로 모읍니다.
    *   결과: `1c, 3a, 3b, 7d, 7g, 7e`

### 강의 맥락
교수님은 딕셔너리 구현 방식 중 해싱(hashing) 방법을 설명하면서, 이와 유사한 개념으로 버킷 정렬을 복습했습니다.
*   **비교 정렬이 아님**: "This one was also a very clever idea, and the idea is very similar to the hashing actually. So how it worked. It is a non-comparison sort of origin that we studied." 버킷 정렬이 비교 기반이 아닌 정렬 알고리즘임을 강조했습니다.
*   **작동 방식**: "You have this key and information: 7d, 1c, 3a, 7g, 3b, 7e. And we assume that this key is within a certain range of the integer, from 0 to n-1. Then what we did is we created buckets. And we set this large N, which is the bucket size, for example here 10. And we scattered all the items depending on their key. So, 7 should go to 7th bucket, 1 should go to 1st bucket, 3rd, 3rd and 7th. Okay? Once scattered, then we just gathered all the items from the left to the right." 슬라이드의 예시와 정확히 일치하는 설명을 제공하며, 키가 특정 범위 `[0, N-1]` 안에 있다고 가정함을 언급했습니다.
*   **시간 복잡도**: "Therefore, the time complexity becomes bigger of $n + N$. $n + N$, right? And this was the huge difference with other methods. Other quicksort, on average, kinds of people have no way. And Mercer, people have no way. On average, almost every sorting algorithm, people have no way. For this one, not big of $n$, $n$ of $n$, sorry. And all these sorts become $n$ of $n$. But here, there was no $n$ component. It was big of $n + N$, right? So basically big of $n$." 여기서 $n$은 요소의 개수(number of elements)이고, $N$은 버킷의 개수(number of buckets)를 의미합니다. 다른 비교 정렬 알고리즘들의 평균 시간 복잡도인 $O(n \log n)$와 비교하여, 버킷 정렬의 $O(n+N)$가 매우 효율적임을 강조했습니다. 키의 범위가 작으면 사실상 $O(n)$이 될 수 있습니다.

### 시험 포인트
*   ⭐ 버킷 정렬의 **두 가지 주요 단계(scattering, gathering)**와 각 단계의 의미를 이해하는 것이 중요합니다.
*   ⭐ 버킷 정렬의 **시간 복잡도가 $O(n+N)$** 임을 기억해야 합니다. 여기서 $n$은 항목의 수, $N$은 버킷의 수입니다. 이 시간 복잡도는 다른 비교 정렬(예: Quick Sort, Merge Sort의 $O(n \log n)$)과 구별되는 버킷 정렬의 핵심적인 장점입니다.
*   ⭐ 버킷 정렬이 **언제 효율적인지(if keys come from a small interval $[0, N-1]$)** 조건을 이해하고 설명할 수 있어야 합니다. 이는 해싱의 아이디어와 유사하게, 키가 특정 범위 내에 고르게 분포할 때 성능이 극대화됨을 의미합니다.

## Hashing

### 핵심 개념
해싱(Hashing)은 **키(key) 값**을 해시 테이블($HT$) 내의 특정 위치(인덱스)로 매핑하는 과정을 의미합니다.
*   **해시 테이블($HT$)**: 데이터를 저장하는 배열 형태의 자료구조로, $HT[0..M-1]$과 같이 $0$부터 $M-1$까지의 인덱스를 가집니다.
    *   해시 테이블의 각 위치는 **슬롯(slot)**이라고 불립니다.
    *   하나의 슬롯은 일반적으로 하나의 `(key, info)` 쌍(pair)을 저장합니다.
*   **해시 함수 $h()$**: 주어진 키(key)를 해시 테이블의 인덱스 $[0..M-1]$로 매핑하는 함수입니다.

### 코드/수식 해설
*   **해시 테이블 인덱스 범위**: $HT[0..M-1]$은 해시 테이블의 크기가 $M$일 때, $0$부터 $M-1$까지의 정수 인덱스를 가짐을 나타냅니다.
*   **해시 함수 매핑**: $h(): \text{a set of keys} \rightarrow [0..M-1]$
    *   해시 함수 $h()$는 다양한 키(key)들을 입력으로 받아, 해시 테이블의 유효한 인덱스 범위($0$에서 $M-1$ 사이의 정수) 중 하나로 변환하여 출력합니다.

### 구체적 예시
강의에 따르면 `(John, 15)`, `(Mike, 16)`, `(Smith, 15)`, `(Mary, 17)`와 같은 `(키, 정보)` 쌍들을 해시 테이블에 저장하고자 합니다. 이때, 키 값을 `h()` 함수에 입력하면 해당 키가 저장될 해시 테이블의 특정 슬롯 인덱스(예: `John`의 키 `15`를 입력했을 때 `h()`가 `1`을 반환하면 해시 테이블의 `1`번 슬롯)를 얻게 됩니다.

### 강의 맥락
교수님은 해싱이 "해시 테이블"과 "해시 함수"라는 두 가지 주요 요소를 활용한다고 강조하셨습니다. 해시 함수는 키를 입력받아 해시 테이블의 해당 인덱스를 출력하며, 이 과정은 **매우 빨라야 한다**고 설명하셨습니다. 각 블록을 **슬롯**이라고 부르며, 슬롯은 보통 하나의 `(key, info)` 쌍을 저장합니다.

예시로 `John`이 첫 번째 위치에 할당되고, `Smith`도 같은 위치에 할당될 수 있다고 설명하시며, 이처럼 서로 다른 키가 **같은 슬롯으로 매핑되는 현상**을 **충돌(collision)**이라고 정의하셨습니다. 이 충돌이 해시 테이블의 **가장 큰 문제점**이자 앞으로 다룰 중요한 주제임을 시사했습니다.

### 시험 포인트
*   ⭐ **해싱의 두 가지 핵심 구성 요소(해시 테이블, 해시 함수)의 정의와 역할**: 각각 무엇을 의미하며, 어떤 기능을 하는지 정확히 이해해야 합니다.
*   ⭐ **슬롯(slot)**: 해시 테이블 내에서 `(key, info)` 쌍이 저장되는 개별 공간임을 기억하세요.
*   ⭐ **해시 함수의 역할과 중요성**: 키를 인덱스로 매핑하며, 이 과정이 **빠르게** 이루어져야 함을 강조합니다.
*   ⭐ **충돌(Collision)의 개념**: 서로 다른 키가 동일한 해시 테이블 슬롯으로 매핑되는 현상으로, 해싱에서 반드시 해결해야 할 중요한 문제입니다.

## Slide 7

**핵심 개념**
해싱(Hashing)은 키(key) 값을 해시 테이블(Hash Table, $HT$) 내의 특정 위치(인덱스)에 매핑하는 기법입니다. 이는 딕셔너리(Dictionary)와 같은 데이터 타입을 효율적으로 구현하기 위한 핵심 방법입니다.

*   **해시 테이블 (Hash Table)**: 실제 데이터 항목들이 저장되는 배열 형태의 자료구조로, 인덱스 $0$부터 $M-1$까지의 범위를 가집니다.
    *   **슬롯 (Slot)**: 해시 테이블의 각 위치를 슬롯이라고 부르며, 각 슬롯은 일반적으로 하나의 `(key, info)` 쌍을 저장할 수 있습니다.
*   **해시 함수 (Hash Function)**: 주어진 키를 해시 테이블 내의 인덱스, 즉 $0$부터 $M-1$ 사이의 정수로 변환하여 매핑하는 함수입니다.

**코드/수식 해설**
해시 테이블은 $0$부터 $M-1$까지의 인덱스를 갖는 배열 $HT[0..M-1]$로 표현됩니다.
해시 함수 $h()$는 키(key)를 입력받아 해시 테이블의 유효한 인덱스(index)를 출력하며, 다음과 같이 정의됩니다:
$$ h(\text{key}): \text{set of keys} \rightarrow [0..M-1] $$
여기서 $M$은 해시 테이블의 크기이며, 출력되는 `index`는 $0 \le \text{index} \le M-1$ 범위를 가 가집니다.

**구체적 예시**
슬라이드의 다이어그램에서 `(John, 15)`라는 `(key, info)` 쌍이 주어졌을 때, `hash fun` ($h()$)은 `John`이라는 키를 입력받아 계산된 해시 테이블의 인덱스 `1`로 매핑합니다. 따라서 `(John, 15)`는 해시 테이블의 1번 슬롯에 저장됩니다.

**강의 맥락**
교수님은 딕셔너리(Dictionary)의 구현 방식 중 해싱이 "마법 같은(magic)" 평균 $O(1)$의 시간 복잡도를 제공하여 가장 인기가 많다고 강조합니다. 이는 삽입, 삭제, 검색의 시간 복잡도가 데이터 크기 $N$에 비례하지 않고 상수 시간에 가까움을 의미합니다. 버킷 정렬(Bucket Sort)이 키를 이용해 데이터를 '뿌리고 모으는' 방식과 유사하게, 해싱은 키를 해시 테이블의 특정 위치에 직접 매핑하는 방식으로 작동합니다.

이 슬라이드는 해싱의 두 가지 주요 구성 요소를 소개합니다:
1.  **해시 테이블 (Hash Table)**: 실제 `(key, info)` 쌍을 저장하는 배열과 같은 자료구조입니다. 각 항목이 저장되는 위치를 `슬롯(slot)`이라고 부르며, 일반적으로 하나의 슬롯은 하나의 `(key, info)` 쌍을 저장합니다.
2.  **해시 함수 (Hash Function)**: 입력 키를 받아서 해당 키가 저장될 해시 테이블의 `슬롯 인덱스`를 결정하는 함수입니다. 이 함수는 $O(1)$의 매우 빠른 속도로 동작해야 합니다.

강의에서는 `John 15`가 해시 함수를 통해 해시 테이블의 특정 슬롯(예: 인덱스 1)에 저장되는 예시를 들어 기본 개념을 설명합니다. 하지만 만약 `Smith 15`와 같이 다른 키가 동일한 슬롯으로 매핑되는 경우, 이를 ⭐**충돌(Collision)**⭐이라고 부르며, 이는 해시 테이블의 주요 문제점 중 하나로 이후 강의에서 충돌 처리 방법, 해시 함수 설계, 해시 테이블 크기 결정 등 다양한 이슈를 다룰 것임을 예고합니다.

**시험 포인트**
*   ⭐ 해싱은 키 값을 해시 테이블의 특정 위치에 매핑하는 과정이며, 평균적으로 $O(1)$의 매우 빠른 연산 속도를 제공합니다.
*   ⭐ 해시 테이블의 두 가지 핵심 구성 요소는 **해시 테이블(데이터가 저장되는 공간)**과 **해시 함수(키를 인덱스로 변환하는 로직)**입니다.
*   ⭐ 해시 함수 $h()$는 키(set of keys)를 $0$부터 $M-1$까지의 정수 인덱스로 매핑해야 합니다.
*   ⭐ **충돌(Collision)**은 서로 다른 두 개 이상의 키가 해시 함수에 의해 해시 테이블의 동일한 슬롯으로 매핑되는 현상이며, 효율적인 해싱 시스템 설계를 위해 반드시 해결해야 할 문제입니다.

### 핵심 개념
해시 테이블(Hash Table)은 거대한 키 공간($0$부터 $999,999,999$까지 9자리 학생 ID)에 비해 실제 저장할 데이터의 수가 적을 때(예: 1,000명 학생) 메모리 낭비를 줄이고 효율적으로 데이터를 관리하기 위해 사용됩니다. 이는 거대한 키를 작은 인덱스 공간으로 압축하는 해시 함수의 능력을 활용합니다.

### 구체적 예시
9자리 학생 ID로 학생 기록을 저장하는 상황:
*   **문제 1: 왜 `0...999,999,999`로 인덱싱된 일반 배열이 나쁜 생각인가?**
    *   `10^9` 크기의 배열은 정의하고 할당하기에 너무 거대하여 현실적으로 불가능합니다.
*   **문제 2: 학생이 1,000명뿐이라면, 메모리의 어느 정도가 낭비되는가?**
    *   전체 키 공간은 $10^9$이지만, 실제 사용하는 공간은 $10^3$입니다.
    *   낭비되는 메모리 비율은 약 $(10^9 - 10^3) / 10^9 \approx 1 - 10^{-6}$입니다. 즉, 거의 모든 메모리가 낭비됩니다 (대략 $10^6$배 더 많은 공간을 불필요하게 사용).
*   **문제 3: 키의 어떤 속성을 활용하면 이를 효율적으로 압축할 수 있는가?**
    *   키 자체의 중복 없음(9자리 학생 ID는 모두 고유함)과 달리, 키의 거대한 범위($10^9$)에 비해 실제 존재하는 유효한 키의 수(1,000명)는 매우 적다는 속성을 활용합니다.
    *   이 거대한 키 공간을 1,000개의 슬롯을 가진 작은 해시 테이블의 인덱스로 매핑하는 효율적인 해시 함수가 필요합니다.
    *   예를 들어, 학생 ID의 앞 4자리가 연도를 나타내어 중복이 많은 패턴을 보인다면, 이러한 특정 패턴을 고려하여 해시 함수를 설계할 수 있습니다. 즉, 입력 키 분포에 대한 지식을 활용하여 충돌을 최소화하고 균일하게 분배하는 함수를 만드는 것이 중요합니다.

### 강의 맥락
교수님께서는 딕셔너리 자료구조와 이를 구현하는 다양한 방법(정렬/비정렬 리스트, 이진 탐색 트리, AVL 트리 등)을 설명하시면서 해시 테이블의 압도적인 평균 시간 복잡도 $O(1)$의 장점을 강조하셨습니다. 이 퀴즈는 해시 테이블이 왜 필요한지를 이해시키기 위한 문제로, 9자리 학생 ID를 키로 사용하는 상황을 가정하여 일반 배열 사용의 비효율성과 해시 테이블을 통해 이를 어떻게 효율적으로 압축할 수 있는지에 대한 사고를 유도합니다. 특히, 입력 키의 분포 특성(예: 학생 ID의 연도 부분)을 해시 함수 설계에 어떻게 활용할지에 대한 토론을 이끌어내셨습니다.

### 시험 포인트
*   ⭐**희소한 키 공간(sparse key space)에 대한 일반 배열 사용의 비효율성**: 거대한 키 범위에 비해 실제 데이터 수가 적을 때 발생하는 메모리 낭비 문제를 이해해야 합니다.
*   ⭐**해시 테이블의 필요성**: 이러한 비효율성을 해결하기 위해 해시 테이블이 어떻게 키를 압축하고 인덱스를 매핑하는지 이해하는 것이 중요합니다.
*   ⭐**해시 함수 설계의 중요성**: 키의 특정 패턴이나 분포(예: 학생 ID의 연도)를 활용하여 충돌을 최소화하고 데이터를 균일하게 분포시키는 해시 함수를 설계하는 아이디어는 중요한 시험 포인트가 될 수 있습니다.

해싱(Hashing)은 키(key) 값을 해시 테이블(Hash Table, $HT$) 내의 특정 위치(슬롯)에 매핑하는 기법입니다.
*   **해시 테이블 ($HT[0..M-1]$)**: 데이터를 저장하는 배열 형태의 자료구조입니다.
    *   $HT$의 각 위치는 **슬롯(slot)**이라고 불립니다.
    *   일반적으로 하나의 슬롯은 하나의 `(key, info)` 쌍만 저장할 수 있습니다.
*   **해시 함수 ($h()$)**: 키 집합(set of keys)을 해시 테이블의 인덱스 범위 $[0..M-1]$로 매핑하는 함수입니다.

**코드/수식 해설**
해시 함수 $h(key)$는 주어진 `key`를 입력받아, 해시 테이블의 유효한 인덱스인 $0$부터 $M-1$ 사이의 정수 값을 출력합니다. 여기서 $M$은 해시 테이블의 크기입니다.

$$
h(\text{key}) \rightarrow [0..M-1]
$$

**구체적 예시**
슬라이드의 그림에서 `Smith`나 `Mary`와 같은 입력 키(key)는 `h()`라는 해시 함수를 통해 처리됩니다. 이 해시 함수는 각 키에 해당하는 해시 테이블($HT$)의 인덱스를 계산합니다. 예를 들어, `(John, 15)`는 인덱스 $1$에 저장되고, `(Mike, 16)`은 인덱스 $M-1$에 저장될 수 있습니다.

**강의 맥락**
교수님은 해싱이 매우 인기 있는 데이터 저장 방식이며, 평균적으로 $O(1)$의 시간 복잡도를 제공하여 마치 "마법과 같다"고 강조하셨습니다. 이는 데이터베이스의 크기 $N$에 비례하여 검색 시간이 증가하지 않고 상수 시간 내에 아이템을 찾을 수 있다는 의미입니다.

해싱은 크게 두 가지 주요 구성 요소, 즉 `해시 테이블`과 `해시 함수`를 활용합니다.
*   **해시 테이블**: 데이터를 보관하는 자료구조입니다. 슬라이드의 그림처럼 `0`부터 `M-1`까지의 인덱스를 가진 배열로 볼 수 있습니다.
*   **해시 함수**: 키를 입력받아 해시 테이블의 해당 인덱스를 출력하는 함수입니다. 교수님은 `John 15`라는 아이템에서 `15`가 키라고 가정할 때, 해시 함수가 이 키를 처리하여 해시 테이블의 첫 번째 인덱스($1$)로 할당할 수 있다고 설명하셨습니다.

또한, 해시 함수가 키를 받아 해당 인덱스를 제공하는 이 과정은 **매우 빠르게 ($O(1)$)** 수행되어야 한다고 강조하셨습니다. 만약 `John`이 인덱스 $1$에 할당되었는데 `Smith`도 동일한 인덱스 $1$에 할당되는 경우를 **충돌(collision)**이라고 하며, 이는 해시 테이블의 고질적인 문제이자 앞으로 다룰 중요한 주제임을 언급하셨습니다.

*   ⭐ **해싱의 핵심 구성 요소**: 해시 테이블과 해시 함수의 정의 및 역할.
*   ⭐ **해시 함수의 역할**: 키를 해시 테이블의 유효한 인덱스로 매핑.
*   ⭐ **슬롯(Slot)**: 해시 테이블 내 각 저장 공간의 명칭.

## Hashing

### 핵심 개념
해싱(Hashing)은 키(key) 값을 해시 테이블(Hash Table) 내의 특정 위치에 매핑하는 과정입니다. 이는 `키`와 `정보(info)`로 구성된 데이터를 효율적으로 저장하고 검색하기 위한 자료구조입니다.
*   **해시 테이블 ($HT$)**: 데이터가 실제로 저장되는 배열 형태의 자료구조입니다. 인덱스는 $0$부터 $M-1$까지이며, 각 인덱스 위치를 `슬롯(slot)`이라고 부릅니다. 일반적으로 하나의 슬롯은 하나의 `(key, info)` 쌍만 저장할 수 있습니다.
*   **해시 함수 ($h()$)**: 주어진 `키`를 해시 테이블 내의 유효한 인덱스($0$부터 $M-1$ 사이의 정수)로 변환하는 함수입니다. 이상적인 해시 함수는 키를 고르게 분산시켜 충돌을 최소화해야 합니다.
*   **충돌(Collision)**: 서로 다른 두 개 이상의 `키`가 동일한 해시 테이블 인덱스로 매핑되는 현상입니다. 해싱의 본질적인 문제 중 하나로, 효율적인 충돌 해결 전략이 중요합니다.

### 코드/수식 해설
해시 함수 $h()$는 키 집합(a set of keys)을 해시 테이블의 인덱스 범위 $[0..M-1]$로 매핑합니다.
$$
h(\text{key}) \to [0..M-1]
$$
여기서 $M$은 해시 테이블의 크기(슬롯의 개수)를 의미합니다.

### 구체적 예시
강의 자료의 그림은 해싱 과정을 보여줍니다.
1.  `key`가 해시 함수 $h()$에 입력됩니다.
2.  해시 함수는 `key`에 해당하는 해시 테이블의 인덱스를 출력합니다.
3.  `Mary (키: 17)`는 인덱스 `0`에, `John (키: 15)`는 인덱스 `1`에, `Mike (키: 16)`는 인덱스 `M-1`에 성공적으로 저장되었습니다.
4.  그러나 `Smith (키: 15)`도 해시 함수를 거쳐 인덱스 `1`로 매핑되면서, 이미 `John`이 저장되어 있는 `1`번 슬롯에 저장되어야 하는 상황이 발생합니다. 이것이 바로 **충돌(Collision)**입니다.

### 강의 맥락
교수님께서는 해싱이 키와 정보(`key` and `information`)를 가지는 딕셔너리(dictionary) 자료형을 구현하는 매우 인기 있는 방법임을 강조하셨습니다. 정렬되지 않은 리스트($O(N)$), 정렬된 리스트($O(\log N)$), 이진 탐색 트리(평균 $O(\log N)$, 최악 $O(N)$), 균형 잡힌 탐색 트리($O(\log N)$)와 비교하여, 해시 테이블의 가장 큰 장점은 **평균적으로 $O(1)$의 시간 복잡도**로 삽입, 삭제, 검색이 가능하다는 점을 설명하셨습니다. 이는 마치 마법과 같다고 표현하시면서, `N`개의 데이터를 가지고 있어도 검색 시간이 `N`에 비례하지 않는다고 하셨습니다.

또한, 해싱의 두 가지 주요 구성 요소로 **해시 테이블**과 **해시 함수**를 들었습니다. 해시 함수는 `키`를 입력받아 해시 테이블의 해당 인덱스를 출력하며, 이 과정은 **매우 빠르게** 이루어져야 함을 강조하셨습니다.

그림의 예시에서 `John`이 1번 위치에 할당되었는데, `Smith`도 같은 1번 위치에 할당될 수 있음을 보여주며 이를 **충돌(Collision)**이라고 설명하셨습니다. 충돌은 해시 테이블의 피할 수 없는 문제이며, 이는 해시 함수의 불완전성 때문에 항상 발생할 수 있다고 하셨습니다.

### 시험 포인트
*   ⭐ **해싱의 정의**: 키를 해시 테이블의 위치에 매핑하는 과정.
*   ⭐ **해시 테이블과 해시 함수의 역할**: 해시 테이블은 데이터를 저장하는 배열, 해시 함수는 키를 인덱스로 변환하는 함수.
*   ⭐ **슬롯(slot)의 개념**: 해시 테이블의 각 위치.
*   ⭐ **충돌(Collision)의 정의**: 서로 다른 키가 동일한 해시 테이블 인덱스로 매핑되는 현상. 해싱의 핵심 문제이며, 이를 해결하는 방법이 중요합니다.
*   ⭐ **해시 테이블의 평균 시간 복잡도**: $O(1)$ (검색, 삽입, 삭제).

**핵심 개념**
해싱(Hashing)은 효율적인 데이터 저장 및 검색을 가능하게 하지만, 실제 시스템에 적용할 때는 여러 가지 문제에 직면합니다. 이러한 문제들은 해시 테이블의 성능과 안정성을 좌우하며, 주요 고려사항은 다음과 같습니다.

*   **해시 함수 선택**: 키를 해시 테이블의 인덱스로 매핑하는 `h(key)` 함수를 어떻게 설계할 것인가의 문제입니다. 좋은 해시 함수는 키를 해시 테이블 슬롯에 균일하게 분산시켜 충돌을 최소화해야 합니다.
*   **충돌 처리 (Collision handling)**: 두 개 이상의 서로 다른 키가 동일한 해시 테이블 위치로 매핑될 때 발생하는 문제입니다. 충돌은 불가피하게 발생하며, 이를 어떻게 해결할지가 중요합니다.
*   **해시 테이블 크기 (Size of hash table)**: 해시 테이블의 슬롯(slot) 개수를 얼마나 설정할 것인가의 문제입니다. 테이블 크기가 너무 크면 메모리가 낭비되고, 너무 작으면 충돌이 빈번하게 발생하여 성능이 저하될 수 있습니다. 압축률(compressibility)과 충돌 발생률 사이의 균형이 중요합니다.
*   **오버플로우 처리 (Overflow handling)**: 해시 테이블에 더 이상 새로운 `(key, info)` 쌍을 저장할 공간이 없을 때 발생하는 문제입니다. 특히 버킷(bucket) 크기가 1인 경우, 충돌이 곧 오버플로우로 이어지게 됩니다.

**강의 맥락**
교수님은 해시 테이블이 평균적으로 $O(1)$의 시간 복잡도를 가지는 "마법 같은" 데이터 구조지만, 실제로는 여러 가지 문제점(issues)을 해결해야 한다고 강조합니다.

*   **해시 함수 선택**: "How would you choose hash function? How would you design your hash function?" 이 질문은 강의에서 반복적으로 제기되며, 해시 함수가 키를 해시 테이블에 균일하게 분산시켜 충돌을 최소화해야 함을 강조합니다. (이후 강의에서 이상적인 해시 함수의 특성, 키를 정수로 변환하는 방법, Division, Folding, Mid-square 등 구체적인 해시 함수 설계 방법이 다뤄집니다.)
*   **충돌 처리**: "If collision happens, how would you handle it? If more than two items are located to the same location in the hash table, then what are you going to do?" 충돌은 해시 함수의 "불완전성(imperfection)" 때문에 항상 발생할 수 있으며, 이를 해결하기 위한 정책이 필요하다고 설명합니다. (이후 강의에서 Open Hashing (Separate Chaining)과 Closed Hashing (Open Addressing) 등의 구체적인 충돌 처리 기법이 다뤄집니다.)
*   **해시 테이블 크기**: "How to set the size of the hash table?" 해시 테이블 크기를 너무 크게 하면 공간 낭비가 심하고, 너무 작게 하면 충돌이 많아진다는 **트레이드오프(trade-off)** 관계를 설명하며, 적절한 균형점을 찾는 것이 중요하다고 강조합니다.
*   **오버플로우 처리**: "If the old hash tables are occupied, how would you handle it? Like can you save more data? So your data is full, so you cannot hold more data anymore. So how would you do that? So that problem is called as overflow, right?" 해시 테이블이 가득 찼을 때 새로운 데이터를 저장할 공간이 없는 상태를 오버플로우라고 정의하며, 이에 대한 처리 방식도 중요하다고 언급합니다.

**시험 포인트**

*   ⭐ 특히 해시 테이블 크기 결정 시 **충돌 발생률과 압축률 사이의 트레이드오프**는 중요한 개념이므로 기억해두세요.

그리고 해시 함수의 구성 요소에 대해서도 언급하셨습니다.
"해시 함수에는 두 가지 부분이 있습니다. 첫째는 키를 정수로 변환하는 것입니다. 왜냐하면 키가 정수 값이 아닐 수 있기 때문입니다. 키는 문자열, 이미지 등 다양한 형태일 수 있으므로, 이 경우 정수로 변환해야 합니다. 둘째, 이 정수가 계산되면 이를 해시 테이블 내의 슬롯 주소로 매핑해야 합니다."

## Designing Hash Functions

**핵심 개념**:
해시 함수($HF$)를 설계하는 것은 어려운 작업입니다. 이는 일반적으로 입력 키(incoming keys)들이 무작위적으로 고르게 분포하기보다는 특정 패턴을 가지거나 **`highly clustered (poorly distributed)`**, 즉 특정 값에 집중되는 경향이 있기 때문입니다. 이러한 키 분포의 특성에 따라 해시 함수 설계 방식이 달라져야 합니다.

해시 함수를 설계할 때는 두 가지 주요 상황을 고려합니다:
1.  **입력 키 분포에 대해 `know nothing` (아무것도 모르는 경우)**: 이 경우, 키를 해시 테이블의 슬롯에 **`uniform random distribution`**으로 균일하게 분배하는 해시 함수를 목표로 합니다.
2.  **입력 키 분포에 대해 `know something` (어느 정도 아는 경우)**: 이 경우, 입력 분포의 특성을 활용하여 **`distribution-dependent hash function`**을 설계해야 합니다.

**강의 맥락**:
교수님은 해시 함수 설계가 어려운 이유로 "입력 키가 **`highly clustered`**되어 있다"는 점을 강조하셨습니다. 예를 들어, YouTube 서버의 사용자 쿼리 키는 시기(예: 월드컵 시즌)에 따라 특정 키워드에 집중되는 경향이 있어 "매우 상관관계가 높다(highly correlated)"고 설명하셨습니다. 따라서 아무것도 모르는 상황에서 단순히 균일한 해시 함수를 설계하면, 실제로는 클러스터링된 키들에 대해 오히려 많은 충돌(hash collisions)을 유발할 수 있습니다.

해시 함수 설계 시 두 가지 상황에 대한 교수님의 설명은 다음과 같습니다:
*   **`know nothing`**: "사용자로부터 해시 테이블에 대한 어떠한 것도 예상할 수 없다면, 무작위로 균일하게 선택된 해시 함수 출력 값을 제안하는 것이 답일 수 있습니다."
*   **`know something`**: "만약 어떤 종류의 키들이 다른 키들보다 더 자주 관찰된다는 것을 안다면, 이러한 **`highly clustered keys`**에 대해 더 큰 균일성을 제공해야 합니다. 즉, 이러한 클러스터링된 키들에 더 많은 주의를 기울여야 합니다."

**시험 포인트**:
*   ⭐ **해시 함수 설계의 어려움**: 입력 키가 `highly clustered` (poorly distributed) 되는 경향이 있음을 이해하고 설명할 수 있어야 합니다.
*   ⭐ **두 가지 설계 상황**: 입력 키 분포에 대한 정보 유무에 따른 해시 함수 설계 전략(uniform random vs. distribution-dependent)을 구분하고 각각의 특징을 설명할 수 있어야 합니다.

### 핵심 개념

해시 함수는 이상적으로 키를 직접 인덱스로 사용하는 `h(key) = key` 형태로 정의될 수 있지만, 실제 시스템에서는 이러한 방식이 여러 문제점을 야기합니다. 현실적인 해시 함수는 해시 테이블의 크기(`$m$`)와 충돌 발생률 사이에서 균형을 이루어야 하며, 문자열과 같은 비정수형 키를 처리하기 위한 변환 과정이 필수적입니다.

### 강의 맥락

교수님은 이상적인 해시 함수에 대한 퀴즈를 통해 해시 함수의 실제 설계 시 고려해야 할 중요 사항들을 강조하셨습니다.

1.  **"Let `h(key) = key`. No computation, no collisions for distinct keys — perfect!" What's wrong with this idea?**
    *   **강의 설명:** 이 아이디어의 문제점은 해시 테이블 공간을 낭비한다는 점입니다. 만약 키의 범위(예: 9자리 학번)가 매우 넓다면, 그 넓은 키 범위를 모두 수용할 수 있는 거대한 해시 테이블을 미리 만들어야 하므로 매우 비효율적입니다.
    *   **시험 포인트**: ⭐ 이 아이디어는 이상적으로 충돌이 없지만, **메모리(해시 테이블 공간)를 극도로 낭비하여 비실용적**이라는 점이 중요합니다.

2.  **What two competing goals must any real hash function balance?**
    *   **강의 설명:** 해시 함수 설계 시 두 가지 상충하는 목표는 다음과 같습니다:
        *   **압축 능력 (Compressibility)**: 해시 테이블의 크기(`$m$`)를 가능한 한 작게 유지하여 메모리 사용을 효율적으로 하는 것.
        *   **충돌 최소화 (Minimizing Collisions)**: 서로 다른 키가 동일한 해시 값으로 매핑되는 충돌을 가능한 한 줄이는 것.
    *   이 두 가지 목표 사이에는 트레이드오프가 존재합니다. 해시 테이블이 너무 작아지면 충돌이 불가피하게 증가하기 때문입니다.
    *   **시험 포인트**: ⭐ **해시 테이블 크기 최소화(공간 효율성)와 충돌 최소화(시간 효율성)** 사이의 균형이 해시 함수 설계의 핵심입니다.

3.  **If keys are strings (e.g., names), what does "`h(key) = key`" even mean?**
    *   **강의 설명:** 해시 함수는 반드시 정수형 결과(해시 테이블 인덱스)를 반환해야 합니다. 따라서 키가 문자열인 경우, `h(key) = key`는 직접적으로 적용될 수 없습니다. 해시 함수 내부에서 문자열 키를 먼저 정수형으로 변환하는 과정이 필요하며, 그 정수형 값이 해시 테이블의 특정 슬롯으로 매핑되어야 합니다.
    *   **시험 포인트**: ⭐ 해시 함수는 **항상 해시 테이블의 유효한 정수형 인덱스를 반환**해야 하며, 문자열 같은 비정수형 키는 **내부적으로 정수로 변환**하는 과정이 필요합니다.

# Types of Hash Functions

## 핵심 개념
해시 함수는 입력 키를 해시 테이블의 인덱스(슬롯 주소)로 매핑하는 역할을 합니다. 좋은 해시 함수는 충돌을 최소화하고 키를 해시 테이블의 슬롯에 균등하게 분산시켜야 합니다. 다음은 일반적으로 사용되는 해시 함수의 유형입니다.

*   **Division (나눗셈법)**: 키 값을 해시 테이블의 크기($m$)로 나누어 그 나머지를 해시 값으로 사용합니다. 가장 간단한 방법이며, 해시 값이 항상 $0$에서 $m-1$ 범위 내에 있게 합니다.
*   **Folding (폴딩법)**: 키 값을 여러 부분으로 나눈 다음, 이 부분들을 합하여 해시 값을 생성합니다. 긴 키(예: 문자열, 큰 숫자)에 유용합니다.
*   **Mid-square (제곱근의 중간 값)**: 키 값을 제곱한 후, 그 결과의 중간 비트(또는 숫자)들을 추출하여 해시 값으로 사용합니다. 키의 모든 부분이 해시 값에 영향을 미치도록 설계되어 좋은 분포를 보일 수 있습니다.
*   **Digit analysis (숫자 분석법)**: 모든 키가 미리 알려져 있을 때 사용합니다. 키의 숫자들 중 분포가 불균형한(skewed) 자릿수를 제거하고, 나머지 자릿수들을 조작하여 해시 값을 생성합니다.

## 코드/수식 해설
### Division
정수 $x$를 해시 테이블 크기 $m$으로 나눈 나머지 값을 해시 값으로 사용합니다.

```c
int hash(int x, int m) {
    return x % m;
}
```
여기서 $x$는 입력 키, $m$은 해시 테이블의 크기입니다. 결과 값은 항상 $0$에서 $m-1$ 사이가 됩니다.

### Mid-square
키 $x$를 제곱한 후, 그 결과에서 중간 $r$비트를 추출하여 해시 값으로 사용합니다. 해시 테이블의 크기가 $2^r$일 때 적합합니다.

$$
h(x) = \text{middle r bits of } (x^2)
$$

## 구체적 예시
### Folding (키 폴딩 예시)
교수님은 9자리 숫자 키(예: 123456789)를 해시 테이블 슬롯 0-9로 매핑하는 예를 들었습니다.
*   123 | 456 | 789 (세 부분으로 나눔)
*   123 + 456 + 789 = 1368
*   1368 % 10 = 8
이 경우 해시 값은 $8$이 됩니다.

### Mid-square (예시)
키 $4567$을 $100$ 크기의 해시 테이블(두 자리 중간 값)에 매핑한다고 가정합니다.
1.  키를 제곱합니다: $4567^2 = 20857489$
2.  결과에서 중간 두 자리를 추출합니다: $57$
이 경우 해시 값은 $57$이 됩니다. 중간 숫자를 선택하는 이유는 키의 모든 자릿수가 해시 값 결정에 영향을 미치도록 하기 위함입니다.

## 강의 맥락
교수님은 해시 함수의 다양한 유형을 소개하며 이 슬라이드의 내용을 설명했습니다.
*   **Division**: "가장 먼저 살펴볼 것은 나눗셈법입니다. 나눗셈법은 모듈로(%) 연산자를 사용하여 나눗셈의 나머지를 취하고 키 값을 해시 테이블의 범위 내로 유지합니다... $x$ 값을 $m$으로 나눈 나머지를 계산합니다. 여기서 $m$은 해시 테이블의 크기이며, 나눗셈의 나머지는 해시 테이블의 범위 내에 있습니다. 따라서 해시 테이블의 인덱스는 $0$부터 $m-1$까지이며, 이는 이 연산자의 출력과 정확히 일치합니다."
    *   ⭐**시험 포인트**: 나눗셈법에서 해시 테이블 크기 $m$을 선택하는 것이 중요하다고 강조했습니다. 특히 짝수가 아닌 홀수, 가능하면 소수를 사용하는 것이 좋습니다.
*   **Folding**: "또 다른 방법으로 폴딩 키(folded keys)를 사용할 수 있습니다. 이는 입력 키가 12912345679와 같은 긴 숫자일 때... 우리는 이 키를 세 자리씩 나누고 각각을 합산한 후 $10$으로 나눈 나머지를 취할 수 있습니다. 이것이 폴딩 해시 함수 방식입니다." 또한 문자열을 숫자로 변환하여 합산 후 나눗셈법을 적용하는 방법도 언급했습니다.
*   **Mid-square**: "미드스퀘어(mid-square) 방식이라는 또 다른 해시 함수 방법이 있습니다. 이는 정수 키 입력에 정말 좋은 해시 함수 방법입니다. 키가 정수라면 미드스퀘어 방식이 적합합니다. 작동 방식은 키 값을 제곱하고 결과의 중간 $r$ 비트를 취하는 것입니다... 왜 미드스퀘어가 좋은가요? ...이 두 자리(중간 값)는 모든 입력 키의 모든 자릿수로부터 영향을 받습니다. 따라서 입력 키는 이 두 자리를 결정하는 데 중요한 역할을 합니다. 최종 출력에 영향을 미치는 입력 키의 어떤 자릿수도 놓치고 싶지 않습니다. 이것이 미드스퀘어 방식이 널리 사용되고 좋다고 알려진 이유입니다."
    *   ⭐**시험 포인트**: 미드스퀘어 방식이 '좋은' 이유를 설명할 수 있어야 합니다 (키의 모든 자릿수가 해시 값에 영향을 미침).
*   **Digit analysis**: 교수님은 이 슬라이드에서 숫자 분석법에 대한 상세한 설명을 하지는 않고, 다음 슬라이드에서 예시를 들겠다고 언급했지만 실제 음성 전사에서는 곧바로 나눗셈법으로 넘어갔습니다. 따라서 슬라이드에 있는 정의만 반영합니다.

## 시험 포인트
*   ⭐각 해시 함수의 종류(Division, Folding, Mid-square, Digit analysis)와 그 작동 방식을 설명할 수 있어야 합니다.
*   ⭐특히 나눗셈법에서 해시 테이블의 크기 $m$을 소수로 선택해야 하는 이유를 이해하고 설명할 수 있어야 합니다. (짝수나 소수의 배수를 피해야 하는 이유).
*   ⭐Mid-square 방식이 좋은 해시 함수로 간주되는 이유를 설명할 수 있어야 합니다 (모든 키 자릿수가 해시 값에 영향을 미치기 때문).

### 핵심 개념
**나눗셈을 이용한 해싱(Hashing by Division)**은 해시 함수를 구현하는 가장 간단한 방법 중 하나입니다. 입력 키 $x$를 해시 테이블의 크기 $M$으로 나눈 나머지를 사용하여 해시 테이블의 인덱스를 결정합니다. 이 방법은 나머지 연산(`%`)을 통해 모든 키 값을 해시 테이블의 유효한 범위($0$부터 $M-1$) 내로 매핑합니다.

### 코드/수식 해설
나눗셈 해싱 함수는 다음과 같이 구현됩니다.

```c
int hash(int x) {
    return (x % M);
}
```
여기서 $x$는 입력 키(정수), $M$은 해시 테이블의 크기입니다.
수식으로는 $h(x) = x \pmod M$으로 표현할 수 있습니다.
*   $M$은 해시 테이블의 크기입니다.
*   나눗셈 나머지($x \pmod M$)는 항상 $0$에서 $M-1$ 사이의 값을 가지므로, 해시 테이블의 인덱스 범위에 정확히 일치합니다.

### 강의 맥락
교수님께서는 나눗셈 해싱을 가장 먼저 소개하며, "모듈러스(modulus) 연산자를 사용하여 나눗셈의 나머지를 취하는 것"이라고 설명하셨습니다. `M`이 해시 테이블의 크기이며, 나머지 연산의 결과가 "해시 테이블의 범위 내에 놓이게 된다"고 강조하셨습니다.

이상적인 경우, 즉 "키 공간이 모든 정수로 균일하게 분포되어 있다면" 나눗셈 해싱은 균일한 해시 함수가 될 수 있다고 언급하셨습니다. 하지만 실제로는 "들어오는 키들이 매우 밀집되어(highly clustered) 있거나 상관관계가 높은(highly correlated) 경향이 있다"는 점을 지적하며, 이 때문에 "나누는 수($M$)의 선택이 좋은 해시 함수를 만드는 데 매우 중요"하다고 강조하셨습니다. 이는 단순히 나머지 연산을 사용하는 것 이상으로 $M$의 선택이 중요하다는 점을 미리 경고하는 부분이었습니다.

### 시험 포인트
*   나눗셈 해싱의 원리 ($x \pmod M$)와 해시 테이블 인덱스 범위 ($0$부터 $M-1$) 이해하기.
*   ⭐**실제 데이터의 키가 상관관계가 높거나 밀집되어 있을 때, 나눗셈 해싱에서 $M$의 선택이 충돌 최소화에 얼마나 중요한지 설명할 수 있어야 합니다.** 이는 이후 $M$을 짝수가 아닌 홀수, 특히 소수(prime number)로 선택하는 이유와 직접적으로 연결됩니다.

## Slide 18

**핵심 개념**
해시 함수의 일종인 나눗셈(Division) 방식에서 제수($M$)의 선택은 해시 테이블 슬롯에 키를 고르게 분배하는 데 매우 중요합니다. 특히, 짝수 제수($M$)는 입력 키의 홀짝성에 따라 해시 값의 홀짝성이 고정되어 특정 슬롯만 사용될 가능성이 높지만, 홀수 제수($M$)는 입력 키의 홀짝성과 관계없이 다양한 해시 값을 생성하여 슬롯 활용의 균일성을 높입니다.

**코드/수식 해설**
나눗셈 방식의 해시 함수는 다음과 같이 정의됩니다:
$$h(x) = x \pmod M$$
여기서 $x$는 입력 키(정수), $M$은 해시 테이블의 크기이자 제수입니다. 이 연산의 결과는 항상 $0$부터 $M-1$까지의 정수 범위에 속합니다.

**구체적 예시**
1.  **짝수 제수 ($M=14$) 사용 시:**
    *   $20 \pmod{14} = 6$ (짝수 $\to$ 짝수)
    *   $30 \pmod{14} = 2$ (짝수 $\to$ 짝수)
    *   $8 \pmod{14} = 8$ (짝수 $\to$ 짝수)
    *   $15 \pmod{14} = 1$ (홀수 $\to$ 홀수)
    *   $3 \pmod{14} = 3$ (홀수 $\to$ 홀수)
    *   $23 \pmod{14} = 9$ (홀수 $\to$ 홀수)
    이처럼 입력 키의 홀짝성이 해시 값의 홀짝성으로 그대로 연결되어, 홀수 해시 값은 홀수 키에서만, 짝수 해시 값은 짝수 키에서만 생성됩니다.
2.  **홀수 제수 ($M=15$) 사용 시:**
    *   $20 \pmod{15} = 5$ (짝수 $\to$ 홀수)
    *   $30 \pmod{15} = 0$ (짝수 $\to$ 짝수)
    *   $8 \pmod{15} = 8$ (짝수 $\to$ 짝수)
    *   $15 \pmod{15} = 0$ (홀수 $\to$ 짝수)
    *   $3 \pmod{15} = 3$ (홀수 $\to$ 홀수)
    *   $23 \pmod{15} = 8$ (홀수 $\to$ 짝수)
    입력 키의 홀짝성과 관계없이 해시 값이 홀수 또는 짝수 슬롯으로 혼합되어 매핑될 수 있습니다.

**강의 맥락**
교수님은 해시 함수에서 제수 $M$의 선택이 중요하며, 특히 짝수와 홀수 중 어떤 것을 선택해야 하는지에 대해 설명합니다. 짝수 $M$을 사용하면, 입력 키의 홀짝성에 따라 해시 결과의 홀짝성이 결정되는 문제가 발생한다고 강조합니다. 예를 들어, $M=14$를 사용하면 짝수 입력은 짝수 해시 값으로, 홀수 입력은 홀수 해시 값으로만 매핑됩니다. 만약 입력 키 분포가 짝수(또는 홀수)에 편향되어 있다면, 해시 테이블의 짝수(또는 홀수) 슬롯만 집중적으로 사용되어 충돌이 빈번하게 발생하고 전체 해시 테이블이 균일하게 활용되지 못하는 문제가 생긴다고 설명합니다. 반면, 홀수 $M$을 사용하면 입력 키의 홀짝성과 무관하게 해시 값이 홀짝 슬롯에 섞여서 매핑될 수 있으므로, 입력 분포가 편향되어 있더라도 그 편향을 약화시키고 슬롯을 더 균일하게 활용할 가능성이 높아진다고 설명합니다.

**시험 포인트**
*   ⭐**나눗셈 해시 함수에서 제수 ($M$)를 짝수로 선택했을 때의 문제점과 이유를 설명할 수 있어야 합니다.** (입력 키의 홀짝성이 해시 값의 홀짝성으로 직접 연결되어 슬롯 활용이 편향될 수 있음)
*   ⭐**나눗셈 해시 함수에서 제수 ($M$)를 홀수로 선택하는 것이 왜 더 좋은지 설명할 수 있어야 합니다.** (입력 키의 홀짝성 편향을 완화하고 해시 테이블 슬롯을 더 균일하게 분배하는 데 도움이 됨)
*   ⭐**균일한 해시 테이블 슬롯 분배가 중요한 이유를 이해해야 합니다.** (충돌 최소화 및 검색, 삽입, 삭제 성능 향상)

**핵심 개념**
해시 함수에서 나눗셈 방법($h(x) = x \pmod M$)을 사용할 때, 해시 테이블의 크기 $M$을 선택하는 것이 중요합니다. 특히, $M$을 소수(prime number)로 선택하는 것이 해시 충돌을 최소화하고 키를 해시 테이블 슬롯에 균일하게 분배하는 데 유리합니다.

**강의 맥락**
교수님은 앞서 짝수와 홀수 제수($M$)의 차이를 설명하며 홀수 제수가 더 좋다고 언급했습니다. 이제 한 걸음 더 나아가 $M$을 소수로 선택하는 것이 바람직하다고 강조합니다.

*   **홀수 제수도 편향을 가질 수 있는 경우**: "실제로 홀수 제수도 해시 테이블 슬롯의 편향된 분포를 보일 수 있습니다." 이는 제수가 3, 5, 7과 같은 작은 소수들의 배수일 때 발생합니다. (예: $M=651 = 3 \times 7 \times 31$은 홀수이지만, 작은 소수 인수를 포함하고 있어 잠재적인 편향을 가집니다.)
*   **소수 인수의 영향**: "하지만 $M$의 각 소수 인자 $p$의 부정적인 영향은 $p$가 커질수록 감소합니다." 즉, $M$을 구성하는 소수 인자들이 클수록 해시 값 분포에 미치는 나쁜 영향이 줄어든다는 것입니다.
*   **이상적인 $M$ 선택**:
    *   ⭐"이상적으로는 큰 소수 $M$을 선택해야 합니다."
    *   "대안적으로는 $M$이 작은 소수 인자($\le 20$)를 갖지 않도록 선택합니다."
    *   예시를 통해 이를 설명합니다: "$M=651 (= 3 \times 7 \times 31)$: Bad", "$M=713 (= 23 \times 31)$: Good" $651$은 $3$과 $7$ 같은 작은 소수 인수를 가지는 반면, $713$은 $23$과 $31$처럼 비교적 큰 소수 인수를 가져 더 나은 선택이 됩니다.
*   **나눗셈 연산의 영향**: "주어진 큰 입력 숫자 집합에 대해 모듈로 연산이 해시 값 분포에 어떻게 영향을 미치는지가 중요합니다." 큰 소수 인자는 해시 테이블 전반에 걸쳐 해시 값 분포에 덜 영향을 미칩니다. 즉, 입력 키가 특정 패턴을 가지더라도 큰 소수로 나누면 해시 값이 더 고르게 분포될 가능성이 높아집니다.

**시험 포인트**
*   ⭐해시 테이블의 제수 $M$을 선택할 때, **큰 소수**를 사용하는 것이 왜 중요한지 이해하고 설명할 수 있어야 합니다.
*   ⭐$M$이 작은 소인수를 가지는 경우(예: $M=651$)와 큰 소인수를 가지는 경우(예: $M=713$)의 차이를 이해하고, 이것이 해시 충돌에 어떤 영향을 미 미치는지 설명할 수 있어야 합니다. 이는 입력 키가 균일하게 분포되지 않았을 때 편향을 줄이는 데 핵심적인 요소입니다.

## Slide 20

## Why Prime Number?

### 핵심 개념
Division Hashing (제산법)에서 해시 테이블의 크기 $M$을 소수(Prime Number)로 선택하는 것이 중요한 이유에 대해 설명합니다. 이는 특히 입력 키(Input Keys)가 특정 패턴을 가지거나 무작위 분포가 아닐 때 해시 충돌(Hash Collision)을 최소화하고 데이터를 해시 테이블 슬롯에 고르게 분산시키기 위함입니다.

### 구체적 예시

1.  **입력 키가 균일하게 분포된 경우**:
    *   입력 키가 균일 무작위 분포(uniformly-random distributed)를 가진다면, 해시 테이블 크기 $M$이 소수일 필요는 없습니다. 이때는 짝수 제수($M$)를 사용해도 문제가 없습니다.
    *   ⭐ 하지만 현실에서는 입력 키가 **상관관계**를 가지거나 **특정 패턴**을 보이는 경우가 많으므로, 이러한 상황에 대비하여 제수 $M$ 선택이 중요해집니다.

2.  **입력 키에 특정 패턴이 있는 경우 (Key mod $M$ 예시)**:
    *   **입력 키**: `10, 20, 30, 40, 50` (10의 배수 패턴)
    *   **`Key mod 4` (짝수 제수)**
        *   `10 mod 4 = 2`
        *   `20 mod 4 = 0`
        *   `30 mod 4 = 2`
        *   `40 mod 4 = 0`
        *   `50 mod 4 = 2`
        *   **결과**: `2, 0, 2, 0, 2`
        *   **문제점**: 해시 값이 `0`과 `2`에만 집중되어 심한 충돌이 발생합니다. (bad)
    *   **`Key mod 7` (홀수 및 소수 제수)**
        *   `10 mod 7 = 3`
        *   `20 mod 7 = 6`
        *   `30 mod 7 = 2`
        *   `40 mod 7 = 4`
        *   `50 mod 7 = 1`
        *   **결과**: `3, 6, 2, 4, 1`
        *   **개선점**: 해시 값이 `0`부터 `6`까지 고르게 분포되어 충돌이 줄어듭니다. (better)
        *   이는 제수 $M$을 홀수로 사용하면 입력 키가 짝수/홀수에 편향되어 있더라도 해시 값이 짝수/홀수 슬롯에 고르게 섞여 분산되기 때문입니다.

3.  **작은 소수 vs 큰 소수**:
    *   **입력 키**: `10, 20, 30, 40, 50`
    *   **`Key mod 5` (작은 소수 제수)**
        *   `10 mod 5 = 0`
        *   `20 mod 5 = 0`
        *   `30 mod 5 = 0`
        *   `40 mod 5 = 0`
        *   `50 mod 5 = 0`
        *   **결과**: `0, 0, 0, 0, 0`
        *   **문제점**: 입력 키들이 제수 $M$의 배수이기 때문에 모든 해시 값이 `0`으로 집중되어 심한 충돌이 발생합니다. (bad)
    *   **결론**: 제수 $M$으로 소수를 선택하더라도, 입력 키가 그 소수의 배수일 가능성이 있다면 충돌이 발생할 수 있습니다. 이를 방지하기 위해 ⭐ **충분히 큰 소수**를 사용하는 것이 좋습니다. 큰 소수를 사용하면 입력 키가 해당 소수의 배수일 확률이 낮아져 해시 충돌 가능성이 줄어듭니다.

### 강의 맥락
교수님은 "만약 입력 키가 균일하게 분포되어 있다면 소수 제수를 사용할 필요가 없다"고 설명하며, 실제 문제 상황은 입력 키가 패턴을 가질 때 발생한다고 강조합니다. `Key mod 4`와 `Key mod 7` 예시를 통해 홀수 제수가 더 나은 이유를 설명하며, 짝수 제수는 입력 키의 짝수/홀수 편향이 최종 해시 테이블에도 그대로 전달될 수 있음을 지적합니다. `Key mod 5` 예시를 통해서는 작은 소수라도 입력 키가 그 소수의 배수일 경우 심각한 충돌이 발생할 수 있으므로, ⭐ "이상적으로는 **큰 소수 $M$**을 선택해야 한다"고 다시 한번 강조합니다. 큰 소수를 사용하면 키가 소수의 배수일 확률이 낮아져 분산에 유리합니다.

### 시험 포인트
*   ⭐ **나쁜 해시 함수의 특징**: 입력 키가 특정 패턴을 가질 때, 해시 값이 특정 슬롯에 집중되어 충돌이 심하게 발생하는 경우를 이해하고 설명할 수 있어야 합니다. (예: `Key mod 4` 또는 `Key mod 5`의 문제점)
*   ⭐ **좋은 제수($M$) 선택 기준**: Division Hashing에서 $M$을 소수로 선택해야 하는 이유와 특히 **큰 소수**를 선택하는 것이 유리한 이유를 설명할 수 있어야 합니다. (입력 키의 상관관계, $M$의 배수 문제 등)

## Slide 21

**핵심 개념**
String Folding Method (문자열 폴딩 방식)은 문자열 형태의 키를 해시 테이블의 색인(index)으로 매핑하기 위한 해시 함수 기법 중 하나입니다. 이 방법은 문자열을 구성하는 각 문자의 ASCII 값을 합산하거나, 키 값을 여러 부분으로 나누어 합쳐서 하나의 정수 해시 값을 생성한 후, 해시 테이블 크기 $M$으로 나눈 나머지를 최종 해시 주소로 사용합니다.

**코드/수식 해설**

아래 코드는 문자열을 폴딩하는 간단한 해시 함수의 예시입니다.

```c
int hash(char* x) {
    int i, sum;
    for (sum=0, i=0; x[i]!='\0'; i++)
        sum += (int)x[i];
    return (sum % M);
}
```
*   `char* x`: 입력으로 주어지는 문자열 키입니다.
*   `for (sum=0, i=0; x[i]!='\0'; i++)`: 문자열의 첫 번째 문자부터 끝(`\0`)까지 반복합니다.
*   `sum += (int)x[i];`: 각 문자 `x[i]`를 해당 문자의 정수(ASCII) 값으로 변환하여 `sum`에 누적합니다.
*   `return (sum % M);`: 모든 문자의 ASCII 값을 합산한 `sum`을 해시 테이블의 크기 $M$으로 나눈 나머지 값을 반환합니다. 이 값이 최종 해시 주소가 됩니다.

**구체적 예시**

*   **문자열 키**: "POSTECH"
    *   P의 ASCII 값 + O의 ASCII 값 + S의 ASCII 값 + T의 ASCII 값 + E의 ASCII 값 + C의 ASCII 값 + H의 ASCII 값 = `sum`
    *   최종 해시 값: `sum % M`
*   **폴드된 숫자 키**: 9자리 학생 ID "123456789" (가상의 예시)
    *   이 키를 세 부분으로 나눕니다: 123, 456, 789
    *   각 부분을 합산합니다: $123 + 456 + 789 = 1368$
    *   해시 테이블 크기 $M=10$이라고 가정하면, 최종 해시 값은 $1368 \pmod{10} = 8$이 됩니다.

**강의 맥락**
교수님은 문자열 폴딩 방식에 대해 설명하며, 입력 키가 문자열인 경우 이를 정수 값으로 변환하는 과정이 필요하다고 강조했습니다. 슬라이드에 제시된 코드는 각 문자를 ASCII 값으로 해석하고 이들을 단순히 합산하여 중간 `sum` 값을 만든 뒤, 이 `sum`을 해시 테이블 크기 $M$으로 나눈 나머지를 최종 해시 인덱스로 사용하는 방법을 보여줍니다. 이는 **문자열 키를 정수로 매핑한 후 나눗셈 해시(Division Method)를 적용하는 방식**의 한 예시입니다.

교수님은 또한 `folded keys`라는 개념을 언급하며, 9자리 숫자 키를 3자리씩 여러 부분으로 나누어 합산하고 모듈로 연산을 적용하는 다른 형태의 폴딩 예시를 들어, 키 값을 여러 부분으로 분리하여 조합하는 것이 폴딩 방식의 일반적인 아이디어임을 설명했습니다. 이는 슬라이드 하단의 "Breaking up the key value into several parts & combine them in some way"라는 설명과도 일치합니다.

**시험 포인트**
*   ⭐ **문자열 키를 정수 해시 값으로 변환하는 방법 (예: ASCII 값 합산)**을 이해하는 것이 중요합니다.
*   ⭐ **나눗셈 해시($sum \pmod M$)를 적용하여 최종 해시 테이블 인덱스를 얻는 과정**을 숙지해야 합니다.
*   ⭐ **Folding Method의 기본 아이디어 (키를 여러 부분으로 나누어 조합)**를 파악해야 합니다.

## Slide 22

### 핵심 개념
폴딩(Folding) 해싱은 길이가 긴 키를 여러 부분으로 나누어 합산한 후, 해시 테이블의 크기로 나눈 나머지를 해시 값으로 사용하는 방법입니다. 특히 문자열(string) 키의 경우, 각 문자를 ASCII 코드와 같은 정수로 변환하여 폴딩 방식에 적용할 수 있습니다.

### 코드/수식 해설
주어진 키 $K$ (예: `123456789`)를 여러 부분 $K_1, K_2, \dots, K_n$으로 나눕니다 (예: `123`, `456`, `789`). 해시 테이블의 크기가 $m$일 때, 폴딩 해시 함수 $h(K)$는 다음과 같이 정의됩니다.

$$h(K) = (K_1 + K_2 + \dots + K_n) \pmod m$$

예를 들어, 키 `123456789`를 `10`개의 슬롯을 가진 해시 테이블에 매핑하는 경우:
$$h(123456789) = (123 + 456 + 789) \pmod{10}$$
$$h(123456789) = (1368) \pmod{10}$$
$$h(123456789) = 8$$

문자열 키를 사용하는 경우, 각 문자의 ASCII 값을 이용해 정수로 변환한 후 위 수식을 적용할 수 있습니다. 예를 들어, 문자 `$`의 ASCII 십진수 값은 `36`입니다.

### 구체적 예시
*   **키**: `123456789`
*   **해시 테이블 크기**: `0`부터 `9`까지 (총 10개 슬롯)
*   **폴딩 방법**:
    1.  키 `123456789`를 세 개의 부분 키로 나눕니다: `123`, `456`, `789`.
    2.  이 부분 키들을 합산합니다: `123 + 456 + 789 = 1368`.
    3.  합산된 값을 해시 테이블 크기(10)로 나눈 나머지를 최종 해시 값으로 사용합니다: `1368 mod 10 = 8`.
    따라서 키 `123456789`는 해시 테이블의 `8`번 슬롯에 매핑됩니다.

*   **문자열 적용 예시**:
    슬라이드 우측의 ASCII 테이블은 각 문자가 십진수, 16진수, 8진수 값으로 어떻게 매핑되는지 보여줍니다. 예를 들어, `A`는 십진수 `65`에 해당합니다. 문자열 키를 폴딩 방식으로 해싱하려면, 문자열 내 각 문자를 해당 ASCII 값으로 변환한 후, 이 값들을 합산하여 모듈러 연산을 수행하면 됩니다.

### 강의 맥락
교수님은 해시 함수의 다양한 구현 방법 중 하나로 'string folding method'를 소개하며, 문자열 키를 정수로 매핑하는 필요성을 강조했습니다. 긴 숫자 키 `123456789`를 `123`, `456`, `789`로 분리하여 합산 후 모듈러 10 연산을 통해 해시 값을 얻는 과정을 구체적인 예시로 설명했습니다. 이는 'folded hash function scheme'의 한 예시입니다. 또한, 키가 문자열인 경우 각 문자를 ASCII 값과 같은 'integer number'로 해석하여 합산한 후 모듈러 연산을 적용할 수 있으며, 이 과정을 위해 ASCII 테이블이 활용될 수 있음을 언급했습니다 (ASCII 테이블을 외울 필요는 없음).

### 시험 포인트
*   ⭐ 폴딩 해싱의 기본 개념과 긴 키를 여러 부분으로 나누어 해시 값을 계산하는 과정을 정확히 이해하고 적용할 수 있어야 합니다.
*   ⭐ 문자열 키가 주어졌을 때, 각 문자의 ASCII 값을 사용하여 폴딩 해싱을 적용하는 방법을 설명할 수 있어야 합니다.

### 핵심 개념
Mid-Square Method는 ⭐**정수(integer) 키 값**에 효과적인 해시 함수이다. 이 방법은 키 값을 제곱한 뒤, 결과 값에서 중간 $r$ 비트(또는 자릿수)를 추출하여 해시 주소로 사용한다.

### 코드/수식 해설
이 메서드는 두 단계로 구성된다:
1.  **키 값 제곱**: 주어진 키 값 $x$를 제곱한다.
    $$ \text{squared\_value} = x^2 $$
2.  **중간 비트 추출**: 제곱된 `squared_value`에서 중간 $r$ 비트를 추출한다. 이 $r$ 값은 해시 테이블의 크기 $M$에 따라 결정되며, 보통 $M=2^r$인 경우 $0$부터 $2^r-1$ 범위의 값을 얻게 된다.

### 구체적 예시
십진수를 사용하는 경우의 예시:
*   **키**: `4567` (4자리 숫자)
*   **목표**: 크기 $M = 100$인 해시 테이블에 해싱 (이는 $0$부터 $99$까지 두 자릿수에 해당하므로 $r=2$로 볼 수 있다.)
*   **과정**:
    1.  키 `4567`을 제곱한다: $4567^2 = 20857489$
    2.  결과 `20857489`에서 중간 두 자릿수를 추출한다: `57`
*   따라서 해시 값은 `57`이 된다.

### 강의 맥락
*   교수님은 이 방법이 ⭐**정수형 키**를 다룰 때 매우 유용하다고 강조했다.
*   예시를 통해 `4567`을 제곱하여 `20857489`를 얻고, 해시 테이블 크기가 100이라면 (즉, 0-99의 두 자릿수를 사용한다면) 중간 두 자릿수인 `57`을 최종 해시 값으로 사용한다고 설명했다.
*   ⭐**Mid-Square Method가 좋은 이유**에 대해 교수님은 상세히 설명했다. 제곱 연산의 특성상, 결과 값의 중간 자릿수는 원래 입력 키의 **모든 자릿수**로부터 영향을 받는다. 예를 들어, `4567`을 제곱했을 때 `57`이라는 중간 자릿수는 `4, 5, 6, 7` 모든 숫자의 곱셈 결과에 의해 영향을 받는다. 이처럼 입력 키의 모든 부분이 해시 값 결정에 기여하게 되면, 특정 키 값 편향에 덜 민감하고 해시 값들이 더 균일하게 분포될 수 있어 충돌 가능성을 줄일 수 있다.

### 시험 포인트
*   ⭐Mid-Square Method는 정수 키에 적합한 해시 함수이며, 키를 제곱한 후 결과 값의 중간 $r$ 비트를 해시 값으로 추출한다.
*   ⭐이 방법의 장점은 결과의 중간 자릿수가 입력 키의 모든 자릿수에 의해 영향을 받아 해시 값의 균일한 분포에 기여한다는 점이다.

## Slide 24

**핵심 개념**
미드-스퀘어(Mid-Square) 해싱은 키를 제곱한 후 결과 값의 중간 부분을 해시 테이블 주소로 사용하는 해시 함수입니다. 이 방법은 원래 키의 모든 자릿수가 최종 해시 값에 영향을 미치도록 하여, 키의 분포를 해시 테이블 슬롯에 고르게 분산시키는 데 효과적입니다.

**코드/수식 해설**
미드-스퀘어 해싱 과정은 다음과 같습니다:
1. 입력 키($K$)를 제곱합니다: $K^2$.
2. 이 제곱 값의 중간 $r$비트(또는 자릿수)를 추출하여 해시 값으로 사용합니다. 이는 해시 테이블의 크기($M$)가 $2^r$일 때 효과적입니다. 예를 들어, 해시 테이블 크기가 $100$이라면, $r=2$ (두 자릿수)를 추출하여 $0$에서 $99$ 사이의 값을 얻을 수 있습니다.

슬라이드의 예시는 키 $4567$을 제곱하는 과정을 보여줍니다:
$4567 \times 4567 = 20857489$

여기서 해시 테이블 크기가 $100$이라고 가정할 경우, 중간 두 자릿수인 $57$을 해시 값으로 취합니다.

**구체적 예시**
슬라이드의 예시에서 키 $4567$을 제곱한 결과는 $20857489$입니다. 곱셈 과정을 시각화하여 각 자릿수($4, 5, 6, 7$)가 최종 결과의 중간 두 자릿수($57$)에 어떻게 영향을 미치는지 보여줍니다.
- 빨간색 선은 원본 키의 첫 번째 자릿수($4$)가 최종 결과의 여러 위치에 영향을 미치며, 특히 중간 두 자릿수($57$)에도 영향을 줌을 나타냅니다.
- 초록색, 주황색, 파란색 선은 각각 원본 키의 $5, 6, 7$ 자릿수 역시 중간 두 자릿수($57$)에 복합적으로 영향을 주고 있음을 보여줍니다.

**강의 맥락**
교수님은 미드-스퀘어 방법의 작동 방식을 설명한 후, "왜 미드-스퀘어 방식이 좋은가?"라는 질문에 대한 답변으로 슬라이드의 내용을 강조합니다. 키 $4567$의 제곱 예시를 들며, "중간 두 자릿수($57$)는 원래 키의 모든 자릿수($4, 5, 6, 7$)의 영향을 받는다"고 설명합니다. 이는 "입력 키의 모든 자릿수가 최종 출력(해시 값)을 결정하는 데 중요한 역할을 하기 때문"이며, "어떤 자릿수도 최종 결과에 영향을 미치지 않고 누락되는 것을 원치 않기 때문"이라고 강조합니다. 이처럼 키의 모든 부분이 해시 값 결정에 관여함으로써 더 좋은 해시 분포를 기대할 수 있습니다.

**시험 포인트**
*   ⭐ **미드-스퀘어 해싱이 좋은 이유**: 키의 모든 자릿수가 최종 해시 값(특히 중간 부분)에 영향을 미쳐 균일한 분포를 유도하기 때문입니다.
*   미드-스퀘어 해싱의 기본적인 동작 방식 (키 제곱 후 중간 비트/자릿수 추출).

## Quiz

**핵심 개념**:
해시 함수 $h(k) = k \mod M$를 사용하여 메모리 주소(항상 8의 배수)를 해싱할 때, 제수 $M$의 선택이 해시 테이블 슬롯 활용도 및 충돌 발생에 미치는 영향을 이해합니다. 특히 입력 키가 특정 패턴을 가질 때 소수 $M$의 중요성을 알아봅니다.

**코드/수식 해설**:
해시 함수는 입력 키 $k$를 해시 테이블의 인덱스로 매핑합니다.
$$h(k) = k \mod M$$
여기서 $k$는 해싱될 키(메모리 주소), $M$은 해시 테이블의 크기이자 제수입니다. `%` 연산자는 $k$를 $M$으로 나눈 나머지를 반환하여, 결과값이 $0$부터 $M-1$ 범위에 속하도록 합니다.

**구체적 예시**:
강의에서 다뤄진 퀴즈를 통해 $M$의 선택이 왜 중요한지 살펴봅니다. 입력 키 $k$는 항상 8의 배수($8x$ 형태)입니다.

1.  **$M=16$일 경우**:
    *   입력 키가 8의 배수이므로, $k$는 $8, 16, 24, 32, \dots$ 와 같습니다.
    *   $h(8) = 8 \mod 16 = 8$
    *   $h(16) = 16 \mod 16 = 0$
    *   $h(24) = 24 \mod 16 = 8$
    *   $h(32) = 32 \mod 16 = 0$
    *   결과적으로 해시 값은 항상 $0$ 또는 $8$이 됩니다.
    *   **슬롯 사용**: 16개의 슬롯 중 단 2개(0번, 8번)만 사용되며, 심각한 충돌이 발생합니다.

2.  **$M=17$ (소수)일 경우**:
    *   $M=17$은 8과 서로소(relatively prime)인 소수입니다.
    *   입력 키가 8의 배수여도 $k \mod 17$은 $0$부터 $16$까지 모든 슬롯을 고르게 활용할 수 있습니다.
    *   예를 들어, $h(8) = 8$, $h(16) = 16$, $h(24) = 7$, $h(32) = 15$, $h(40) = 6$, $h(48) = 14$, $h(56) = 5$, $h(64) = 13$, $h(72) = 4$, $h(80) = 12$, $h(88) = 3$, $h(96) = 11$, $h(104) = 2$, $h(112) = 10$, $h(120) = 1$, $h(128) = 9$, $h(136) = 0$ (다시 8의 배수).
    *   **슬롯 사용**: 모든 17개의 슬롯이 균등하게 활용될 수 있습니다.

**강의 맥락**:
교수님은 메모리 주소(항상 8의 배수)를 $k \mod M$ 해시 함수로 처리하는 퀴즈를 제시했습니다.

*   **$M=16$일 때**: 교수님은 "만약 $M=16$을 사용한다면, 모든 메모리 주소가 8의 배수이기 때문에 결과 해시 함수 값은 항상 0 또는 8이 될 것"이라며, "그러면 많은 해시 충돌이 발생하고, 16개의 슬롯 중 오직 2개의 슬롯만 사용될 것"이라고 설명했습니다. 이는 '좋지 않다'고 강조되었습니다. ⭐**시험 포인트**: 특정 패턴을 가진 입력 키와 $M$이 서로소가 아닐 때 발생하는 심각한 슬롯 비효율성.

*   **$M=17$ (소수)일 때**: 교수님은 "만약 $M=17$을 선택한다면 훨씬 나아질 것"이며, "실제로 모든 슬롯을 활용할 수 있을 것"이라고 학생의 답변을 긍정했습니다. 이어서 "모든 해시 테이블 슬롯을 활용할 수 있을 것"임을 확인하고 직접 해보라고 권장했습니다.

*   **일반화**: "언제 소수 $M$을 선택하는 것이 가장 중요할까?"라는 질문에 대해 교수님은 "이는 입력 키들이 균일하게 분포되어 있지 않기 때문"이라고 답했습니다. 즉, "입력 키가 어떤 내부 구조나 특정 패턴을 가질 때" (예: 메모리 주소가 8의 배수) 소수 $M$을 사용하는 것이 중요하다고 강조했습니다. "실제 세계에서 거의 모든 데이터는 그 자체가 매우 클러스터링되어 있기 때문에, 비랜덤 입력을 다룰 때는 해시 함수를 정말 잘 설계해야 한다"고 덧붙였습니다. ⭐**시험 포인트**: 입력 키 분포가 비균일하거나 특정 패턴을 가질 때(즉, 입력이 '비랜덤'일 때) 소수 $M$을 사용하여 충돌을 최소화하고 슬롯을 균등하게 활용하는 것이 핵심입니다.

### 핵심 개념

해싱 기법은 크게 **정적 해싱 (Static hashing)**과 **동적 해싱 (Dynamic hashing)**으로 나뉩니다.

*   **정적 해싱 (Static hashing)**:
    *   해시 함수와 해시 테이블($HT$)의 크기($M$)가 **고정**됩니다.
    *   충돌(collision)이나 오버플로우(overflow) 발생 시 처리하는 방식에 따라 **오픈 해싱 (Open hashing)** 또는 **분리 연결법 (Separate chaining)**과 **폐쇄 해싱 (Closed hashing)** 또는 **개방 주소법 (Open addressing)**으로 구분됩니다. (⭐이 두 용어가 매우 혼동되기 쉬우므로 주의해야 합니다.)
    *   데이터가 시간에 따라 증가하면 성능이 저하될 수 있으며, 해시 구조를 재구성해야 할 때 비용이 많이 듭니다.
*   **동적 해싱 (Dynamic hashing)**:
    *   해시 함수와 해시 테이블($HT$) 크기가 **동적으로 변경**될 수 있습니다.
    *   주요 종류로는 확장형 해싱 (Extensible hashing)과 선형 해싱 (Linear hashing)이 있습니다.
    *   데이터베이스 관리 시스템 (DBMS)과 같이 데이터 크기가 유동적으로 변하는 환경에 적합합니다. (본 강의에서는 깊이 다루지 않습니다.)

### 강의 맥락

교수님께서는 해시 함수 유형에 이어 해싱 방식의 두 가지 큰 분류인 정적 해싱과 동적 해싱을 소개하셨습니다.

"지금까지 우리는 다양한 종류의 해시 함수를 공부했고, 이제 해싱의 유형으로 넘어갈 것입니다. 첫 번째는 정적 해싱이고, 두 번째는 동적 해싱입니다. 우리는 강의에서 이 동적 해싱을 주로 다루지 않을 것입니다. 우리는 주로 이 정적 해싱에 초점을 맞출 것입니다."

**정적 해싱**에 대해 설명하시면서, 해시 함수와 해시 테이블의 크기가 **고정**되어 있음을 강조하셨습니다.
"정적 해싱은 해시 함수, 따라서 해시 테이블의 크기가 고정되어 있다고 가정합니다."
이어서 정적 해싱에서 충돌을 처리하는 두 가지 주요 방법에 대해 설명하며 용어 혼동의 가능성을 지적하셨습니다.
"우리 강의에서는 이 두 가지가 고정된 정적 해싱에 초점을 맞출 것입니다. 그리고 주로 이 해시 충돌, 즉 해시 충돌을 어떻게 처리하는지에 대해 알아볼 것입니다. 두 가지 방법이 있습니다. 하나는 오픈 해싱이고, 다른 하나는 폐쇄 해싱입니다. 그들의 이름 때문에 약간 혼란스럽습니다. 왜냐하면 오픈 해싱은 종종 분리 연결법(separate chaining)이라고 불리고, 폐쇄 해싱은 개방 주소법(open addressing)이라고 불리기 때문입니다. 그래서 매우 혼란스럽습니다. 이것은 오픈 해싱이고, 이것은 개방 주소법입니다. 서로 다릅니다." ⭐

또한, 정적 해싱의 한계점으로 데이터 증가 시 성능이 저하되고 재구성이 비싸다는 점을 언급하셨습니다.
"이 정적 해싱의 성능은 데이터가 시간에 따라 증가함에 따라 종종 용납할 수 없게 됩니다. 그리고 이것은 해시 구조를 특정 시점에서 재구성해야 하는데, 이는 매우 비싼 일입니다."

**동적 해싱**에 대해서는 해시 함수와 해시 테이블의 크기가 **실행 중에 동적으로 변경**될 수 있음을 설명하시며, 데이터베이스 관리 시스템(DBMS)과 같이 데이터 크기가 변하는 실제 시나리오에서 유용하다고 하셨지만, 본 강의에서는 다루지 않는다고 다시 한번 강조하셨습니다.
"하지만 동적 해싱은 해시 함수와 해시 테이블 크기를 실행 중에 동적으로 변경합니다. 물론 많은 실제 시나리오에서 실제 데이터의 증가 또는 감소와 사용자 입력의 경향을 처리하기 위해 해시 테이블 크기 및 해시 함수의 작동 메커니즘을 동적으로 조정하고 싶을 것입니다. 그런 경우 동적 해싱이 종종 사용됩니다. 그래서 이것은 데이터가 크기가 커지고 줄어드는 데이터베이스 관리(DBMS)에 보통 사용됩니다."

### 시험 포인트
*   ⭐**정적 해싱과 동적 해싱의 정의 및 차이점**을 명확히 이해해야 합니다. 특히 **해시 함수 및 해시 테이블 크기의 고정 여부**가 핵심입니다.
*   ⭐정적 해싱의 충돌 처리 방법인 **오픈 해싱 (분리 연결법)**과 **폐쇄 해싱 (개방 주소법)**의 이름과 해당 기술의 **정확한 개념**을 혼동하지 않고 구분할 수 있어야 합니다.

## Slide 27

**핵심 개념**

*   **Open Hashing (오픈 해싱)**: 해시 충돌(collision)을 처리하는 방법 중 하나로, 각 해시 테이블 슬롯에 여러 개의 키-정보 쌍이 저장될 수 있도록 연결 리스트(Linked List)를 사용하는 방식입니다.
*   **Separate Chaining (분리 연결법)**: Open Hashing의 다른 이름입니다.
*   해시 함수 $h()$를 통해 키를 해시 테이블 인덱스로 매핑하며, 동일한 인덱스로 매핑된 항목들은 해당 슬롯에 연결 리스트 형태로 연결됩니다.

**구체적 예시**

*   슬라이드 예시에서 `(John, 15)`와 `(Smith, 20)`는 해시 함수 $h()$를 통해 모두 인덱스 1로 매핑됩니다.
*   `John`이 먼저 삽입되면 해시 테이블 슬롯 1에 저장됩니다.
*   이후 `Smith`가 인덱스 1로 매핑되어 삽입될 때, `John`이 이미 슬롯 1에 있으므로 `John` 뒤에 연결 리스트로 `Smith`를 연결하여 저장합니다.
*   `Mary`는 인덱스 0으로, `Mike`는 인덱스 $M-1$로 매핑되어 각자의 슬롯에 저장됩니다.

**강의 맥락**

*   교수님은 Open Hashing과 Closed Hashing이 해시 충돌을 처리하는 두 가지 주요 기술임을 강조하며, Open Hashing이 **Separate Chaining**으로도 불리는 점 때문에 이름이 혼란스러울 수 있다고 언급했습니다.
*   Open Hashing의 핵심 아이디어는 새로운 항목이 이미 점유된 해시 테이블 슬롯에 삽입될 때, 해당 슬롯에 **연결 리스트(chain)**를 생성하여 항목들을 연결하는 것이라고 설명했습니다.
*   이 방식은 해시 테이블이 **주 메모리(main memory)에 보관될 때 적합**하다고 강조했습니다. 왜냐하면 연결 리스트를 구성하는 `pointer`(`포인터`) 변수는 다음 항목의 메모리 주소를 저장하는데, 모든 데이터가 주 메모리에 있어야 포인터를 통한 접근이 효율적이기 때문입니다.
*   만약 데이터가 너무 커서 주 메모리에 모두 저장할 수 없다면, 포인터가 디스크의 파일 주소를 가리키게 되어 접근 시간이 크게 증가하고 복잡해질 수 있다고 설명했습니다.
*   ⭐**시험 포인트**: Open Hashing이 **Separate Chaining**이라는 다른 이름을 가지며, 충돌 발생 시 **연결 리스트**를 사용하여 처리한다는 점을 이해하는 것이 중요합니다. 또한, 이 방식이 주 메모리 환경에 적합한 이유(포인터를 통한 효율적인 접근)를 아는 것이 중요합니다.

## Slide 28

## Closed Hashing (닫힌 해싱)

### 핵심 개념

**Closed Hashing (닫힌 해싱)**은 충돌 처리 기법 중 하나로, 모든 데이터를 해시 테이블 내부에 직접 저장합니다. 데이터를 저장하기 위해 포인터를 사용하여 외부 체인을 구성하는 오픈 해싱(Open Hashing, 또는 Separate Chaining)과 달리, 닫힌 해싱에서는 추가적인 체인 구조가 없습니다.

*   **슬롯 상태**: 해시 테이블의 각 슬롯은 다음 세 가지 상태 중 하나로 표시됩니다.
    *   **Empty (비어있음)**: 슬롯이 비어 있어 새로운 요소를 삽입할 수 있습니다.
    *   **Occupied (점유됨)**: 슬롯에 이미 요소가 저장되어 있습니다.
    *   **Deleted (삭제됨)**: 이전에 요소가 있었지만 현재는 삭제된 상태입니다.

### 강의 맥락

교수님께서는 'deleted' 상태가 다소 "이상하게 느껴질 수 있다"고 언급하며, "왜 이 슬롯에 'deleted'라는 레이블을 붙여야 하는지"에 대해 깊이 생각해볼 것을 강조하셨습니다. 이 상태는 나중에 검색 과정에서 정확성을 유지하기 위한 목적이 있음을 시사하며, 학생들에게 중요한 사고의 포인트를 제시하셨습니다.

---

### 두 가지 구현 방식

닫힌 해싱은 주로 두 가지 방식으로 구현됩니다.

1.  **Bucket Hashing (버킷 해싱)**
    *   해시 테이블의 슬롯들을 여러 개의 **버킷(buckets)**으로 그룹화합니다.
    *   모든 버킷이 공유하는 **무한 용량의 오버플로우 버킷(overflow bucket)**이 존재합니다.
    *   **강의 맥락**: 교수님은 오버플로우 버킷을 "일종의 속임수(kind of a cheat)"라고 표현하며, 해시 테이블에 맞지 않는 모든 요소들을 저장하는 별도의 데이터 구조임을 설명했습니다.

2.  **Rehashing (재해싱)**
    *   버킷을 사용하지 않습니다 (**No bucketing**).
    *   충돌 발생 시 다른 슬롯을 찾기 위해 **Probing (조사)**이라는 기법을 사용하며, 이를 **Open Addressing (개방 주소법)**이라고도 부릅니다.
    *   **강의 맥락**: 교수님은 재해싱이 "해시 테이블을 가능한 한 많이 활용하려고(exploit this hash table as much as possible)" 노력한다고 설명하며, 오버플로우 버킷 없이 해시 테이블 자체에서 충돌을 해결하려는 방식임을 강조했습니다.

### 시험 포인트

*   ⭐ **Closed Hashing의 세 가지 슬롯 상태 (`empty`, `occupied`, `deleted`)**를 이해하고, 특히 `deleted` 상태가 필요한 이유에 대해 설명할 수 있어야 합니다. (추후 자세히 다뤄질 예정)
*   ⭐ **Closed Hashing의 두 가지 구현 방식 (Bucket Hashing과 Rehashing)**의 주요 특징과 차이점을 숙지해야 합니다.
*   ⭐ **Open Addressing이 Rehashing의 다른 이름**이라는 점을 기억해야 합니다.

### Bucket Hashing

**핵심 개념**:
버킷 해싱(Bucket Hashing)은 폐쇄 해싱(Closed Hashing)의 한 구현 방식으로, 해시 테이블의 슬롯들을 여러 개의 **버킷(buckets)**으로 그룹화하여 사용합니다. 각 버킷은 고정된 수의 슬롯을 가지며, 모든 버킷이 공유하는 **오버플로우 버킷(Overflow Bucket)**을 추가로 유지하여 할당하지 못한 요소를 저장합니다.

**구체적 예시**:
1.  **그룹화**: 해시 테이블의 슬롯들이 특정 기준(예: 2개 슬롯당 1개의 버킷)으로 버킷으로 묶입니다. 슬라이드에서는 `0`번과 `1`번 버킷이 있으며, 각 버킷은 여러 `empty` 슬롯으로 구성됩니다.
2.  **해싱**: `John`, `Mike`, `Smith`, `Mary`와 같은 아이템들은 해시 함수 $h(\cdot)$를 통해 특정 버킷 인덱스로 매핑됩니다. 슬라이드에서는 `John`, `Mike`, `Smith`가 같은 `bucket 1`으로 매핑된다고 가정합니다. 이들은 **동의어(synonyms)**로 불립니다.
3.  **삽입**: 새로운 아이템(예: `John`)이 삽입되면, 해당 아이템이 매핑된 버킷(예: `bucket 1`) 내의 비어있는 슬롯(`empty` 상태)에 저장됩니다.

**강의 맥락**:
교수님은 버킷 해싱이 폐쇄 해싱의 한 종류임을 강조하며, 해시 테이블 슬롯을 버킷으로 그룹화하고 **오버플로우 버킷**을 사용하는 개념을 설명했습니다. 오버플로우 버킷은 "무한한 용량"을 가지며, 어떤 버킷에도 들어가지 못한 요소들을 저장하는 "일종의 치팅(cheat)" 또는 "쓰레기통(trash bin)"으로 비유됩니다. 이는 실제 데이터베이스 관리 시스템에서 데이터가 증가하거나 감소하는 경우에 유용할 수 있다고 언급했습니다. 또한, 실제 버킷 크기는 디스크의 연속된 메모리 공간인 **디스크 블록(disk block)** 크기와 유사하게 설정되는 경우가 많다고 설명했습니다.

**시험 포인트**:
*   ⭐ **버킷 해싱의 정의 및 작동 방식**: 해시 테이블 슬롯을 버킷으로 그룹화하고, 충돌 발생 시 버킷 내 빈 슬롯을 사용하며, 버킷이 가득 찼을 때 오버플로우 버킷을 활용한다는 점.
*   ⭐ **폐쇄 해싱(Closed Hashing)의 한 종류**라는 점.
*   ⭐ **오버플로우 버킷의 역할**: 버킷에 들어가지 못한 요소를 저장하는 보조 저장 공간이라는 점.

## Slide 30

**핵심 개념**:
**버킷 해싱(Bucket Hashing)**은 클로즈드 해싱(Closed Hashing)의 한 구현 방식으로, 해시 테이블의 슬롯들을 여러 개의 **버킷(Bucket)**으로 그룹화하여 충돌을 처리한다. 각 버킷은 고정된 수의 슬롯을 가지며, 키가 해시 함수를 통해 특정 버킷으로 매핑될 때 해당 버킷 내의 빈 슬롯을 찾아 데이터를 저장한다. 만약 버킷이 가득 차면, 모든 버킷이 공유하는 **오버플로우 버킷(Overflow Bucket)**에 데이터를 저장한다. 해시 테이블의 각 슬롯은 `empty`, `occupied`, `deleted` 중 하나의 상태를 가진다.

**구체적 예시**:
1.  **해시 테이블 구조**: 슬라이드 예시에서는 해시 테이블의 슬롯들이 각각 2개의 슬롯을 포함하는 버킷으로 그룹화되어 있다. (`Buckets`)
2.  `Insert(John, D)`: `John`이 해시 함수 `h()`를 거쳐 버킷 1로 매핑되고, 버킷 1의 첫 번째 슬롯에 `John`이 삽입된다. (이 슬라이드에 표시된 현재 상태)
3.  `Insert(Smith, D)`: `Smith` 또한 `h()`를 거쳐 버킷 1로 매핑된다고 가정한다. 버킷 1의 첫 번째 슬롯은 이미 `John`으로 `occupied` 상태이므로, `Smith`는 버킷 1의 다음 빈 슬롯에 삽입된다.
4.  `Insert(Mike, D)`: `Mike` 역시 `h()`를 거쳐 버킷 1로 매핑된다고 가정한다. 만약 버킷 1의 모든 슬롯(`John`과 `Smith` 또는 `deleted` 슬롯)이 가득 차서 더 이상 공간이 없다면, `Mike`는 별도의 **오버플로우 버킷(Overflow Buckets)**에 저장된다.

**강의 맥락**:
- 교수님께서는 **버킷 해싱**이 **클로즈드 해싱**의 두 가지 구현 방식 중 하나라고 설명하셨습니다. (나머지 하나는 Rehashing/Open Addressing)
- 버킷 해싱의 핵심 아이디어는 해시 테이블 슬롯들을 **버킷으로 묶는 것**입니다. 슬라이드의 분홍색 선이 버킷의 경계를 나타내며, 예시에서는 버킷당 두 개의 슬롯으로 구성되어 있습니다. 실제로는 버킷에 몇 개의 슬롯을 둘지(이 버킷 크기)도 설계 시 중요한 파라미터가 됩니다.
- 입력 키(`Mike`, `Smith`, `Mary` 등)는 해시 함수 `h()`를 통해 특정 버킷 인덱스로 매핑됩니다.
- `John`을 삽입하면, `John`의 해시 값이 가리키는 버킷(예: 버킷 1)의 첫 번째 `empty` 슬롯에 저장됩니다.

- ⭐교수님께서는 슬롯이 `empty`, `occupied`, `deleted`의 세 가지 상태를 가진다고 강조하셨습니다. 특히 `deleted` 상태가 필요한 이유에 대해서는 나중에 더 자세히 설명하겠다고 언급하셨는데, 이는 검색 과정에서 잘못된 종료를 막기 위함입니다.
- 만약 특정 버킷의 모든 슬롯이 가득 찼는데 새로운 요소(예: `Mike`)가 해당 버킷으로 매핑될 경우, 이 요소는 **오버플로우 버킷**에 저장됩니다. 이 오버플로우 버킷은 "쓰레기통"이나 "치팅 데이터 구조"처럼 모든 버킷이 공유하는 무한 용량의 저장 공간으로 비유될 수 있습니다.

## Bucket Hashing

### 핵심 개념
Bucket Hashing (버킷 해싱)은 **닫힌 해싱(Closed Hashing)** 기법 중 하나로, 해시 충돌(collision)을 처리하는 방법입니다. 해시 테이블의 슬롯들을 논리적인 그룹인 **버킷(buckets)**으로 묶습니다. 새로운 항목이 해시 충돌을 일으키면, 해당 버킷 내의 비어있는 슬롯을 찾아 저장하고, 해당 버킷이 모두 차면 모든 버킷이 공유하는 **오버플로우 버킷(overflow bucket)**에 저장합니다. 이 기법은 모든 요소를 해시 테이블 내에 직접 저장하는 방식입니다.

### 코드/수식 해설
*   `h()`: 키(key)를 입력받아 해시 테이블 내의 버킷 인덱스를 반환하는 해시 함수입니다.
    *   예시: $h(\text{key}) \rightarrow \text{bucket\_index}$

### 구체적 예시
1.  **`Insert(John, D)`**: `John`이 해시 함수 $h()$를 통해 버킷 1로 매핑됩니다. 버킷 1의 첫 번째 슬롯이 비어있으므로, `John`은 그곳에 삽입됩니다.
    *   `Buckets` (해시 테이블)의 상태: `Bucket 1`의 첫 번째 슬롯에 `John` 저장.
2.  **`Insert(Smith, D)`**: `Smith`도 해시 함수 $h()$를 통해 버킷 1로 매핑됩니다. 하지만 버킷 1의 첫 번째 슬롯은 이미 `John`이 차지하고 있어 충돌(Collision)이 발생합니다.
    *   `Smith`는 버킷 1 내의 다음 빈 슬롯(두 번째 슬롯)에 삽입됩니다.

### 강의 맥락
교수님은 닫힌 해싱(Closed Hashing)의 구현 방식 중 하나로 버킷 해싱을 소개합니다. "해시 테이블의 슬롯들이 버킷으로 그룹화되고, 무한한 용량의 오버플로우 버킷이 유지되며, 이 오버플로우 버킷은 모든 버킷에 의해 공유됩니다."라고 설명합니다. 이는 해시 테이블에 항목을 삽입할 때, 특정 버킷이 가득 찬 경우 항목을 저장할 수 있는 "치트(cheat) 데이터 구조" 역할을 한다고 강조했습니다. 슬라이드에서 `John`과 `Smith`를 버킷 1에 순차적으로 삽입하는 과정을 예시로 들며, `John`이 먼저 삽입되고 `Smith`가 같은 버킷으로 해시되었을 때 충돌이 발생하지만 버킷 내의 다음 빈 슬롯에 `Smith`가 저장되는 과정을 설명합니다. 실제 구현에서 "분홍색 선이나 버킷 당 슬롯 개수를 어떻게 나눌지는 디자인 파라미터"라고 언급하며, 이는 중요한 설계 고려사항임을 시사합니다.

### 시험 포인트
*   ⭐**버킷 해싱의 정의 및 작동 방식**: 해시 테이블 슬롯을 버킷으로 그룹화하고, 버킷 내 빈 슬롯을 탐색하여 충돌을 해결하는 방법임을 이해해야 합니다.
*   ⭐**오버플로우 버킷의 역할**: 버킷이 가득 찼을 때 데이터가 어디로 가는지를 명확히 설명할 수 있어야 합니다. (모든 버킷이 공유하는 오버플로우 버킷으로 이동)
*   ⭐**닫힌 해싱(Closed Hashing)과의 관계**: 버킷 해싱이 닫힌 해싱의 한 종류임을 알아야 합니다.

### 핵심 개념
**버킷 해싱 (Bucket Hashing)**은 **Closed Hashing**의 한 구현 방식으로, 해시 충돌(Collision)을 처리하기 위해 해시 테이블의 슬롯들을 여러 개의 **버킷(Buckets)**으로 그룹화합니다. 각 버킷은 여러 개의 슬롯을 가질 수 있으며, 해시 함수는 키를 특정 버킷에 매핑합니다. 버킷 내의 모든 슬롯이 차면, 아이템은 **오버플로우 버킷(Overflow Bucket)**이라는 별도의 저장 공간으로 이동합니다. 해시 테이블의 각 슬롯은 `empty`, `occupied`, `deleted`의 세 가지 상태 중 하나로 표시될 수 있습니다.

### 구체적 예시
1.  **초기 상태**: 모든 슬롯이 `empty`입니다. `h()` 함수가 키를 받아 해시 테이블의 인덱스를 반환합니다.
2.  **`John` 삽입**: `h(John)`이 `bucket 1`을 가리키고, `bucket 1`의 첫 번째 슬롯이 `empty`이므로 `John`이 삽입됩니다.
3.  **`Smith` 삽입**: `h(Smith)`도 `bucket 1`을 가리킵니다. `bucket 1`의 첫 슬롯은 `John`으로 `occupied` 상태이므로, 다음 `empty` 슬롯(두 번째 슬롯)에 `Smith`가 삽입됩니다.
4.  **`Smith` 삭제**: `Smith`를 찾아서 해당 슬롯을 `deleted`로 표시합니다.
5.  **`Mike` 삽입**: `h(Mike)` 또한 `bucket 1`을 가리킵니다. `bucket 1`을 순회하면 `John`(`occupied`), `deleted` 슬롯을 만나게 됩니다. 초기 설계에서는 `deleted` 슬롯에 새로운 레코드를 저장하지 않는다고 가정하면, `bucket 1`에는 더 이상 `empty` 슬롯이 없습니다. 따라서 `Mike`는 `Overflow Bucket`에 삽입됩니다.
6.  **`Mike` 검색**: `h(Mike)`는 `bucket 1`을 가리키므로 `bucket 1`을 탐색합니다. `John`이 있고, `deleted` 슬롯이 있지만 `Mike`는 없습니다. `deleted` 슬롯을 만나더라도 검색을 중단하지 않고 계속 진행해야 합니다. 버킷 내에서 `Mike`를 찾지 못했으므로, `Overflow Bucket`을 탐색하여 `Mike`를 찾습니다.

### 강의 맥락
교수님은 **Closed Hashing**의 두 가지 구현 방식 중 하나로 **Bucket Hashing**을 설명하며, 해시 테이블의 슬롯을 버킷으로 묶는다고 강조합니다. 각 버킷에는 여러 슬롯이 포함될 수 있으며, 모든 버킷에 공유되는 **무한 용량의 `Overflow Bucket`**이 존재한다고 언급합니다.

`John`과 `Smith`를 `bucket 1`에 삽입하고, 이어서 `Smith`를 삭제하는 과정을 시뮬레이션합니다. 삭제된 슬롯은 `deleted` 상태로 표시되며, 교수님은 이 `deleted` 상태의 필요성을 강조합니다.
⭐ `deleted` 상태는 "검색 프로세스가 다른 키에 대해 잘못 종료되는 것을 방지하기 위해" 사용됩니다. 만약 `deleted` 슬롯을 `empty`로 간주하고 새로운 요소를 바로 삽입한다면, 나중에 해당 버킷의 특정 요소를 찾을 때, `deleted`를 `empty`로 변경한 슬롯에서 검색이 잘못 종료될 수 있기 때문입니다.

이후 `Mike`를 삽입할 때 `bucket 1`에 빈 슬롯이 없으므로 `Overflow Bucket`으로 이동하는 과정을 보여줍니다. `Overflow Bucket`에 있는 데이터를 검색할 때는 `Overflow Bucket` 전체를 탐색해야 하므로 시간이 오래 걸린다는 단점을 지적합니다. 또한, 버킷의 크기는 일반적으로 **디스크 블록(Disk Block)** 크기와 같이 연속적인 메모리 할당이 가능한 물리적 단위로 설정된다고 설명합니다.

### 시험 포인트
*   ⭐ **Bucket Hashing**의 개념과 **Closed Hashing** 내에서의 위치를 설명할 수 있어야 합니다.
*   ⭐ 해시 테이블 슬롯의 **`empty`, `occupied`, `deleted`** 세 가지 상태의 의미와 특히 **`deleted` 상태의 필요성**을 이해해야 합니다. (`deleted` 상태가 검색 효율성에 미치는 영향)
*   ⭐ **`Overflow Bucket`**의 역할과 `Overflow Bucket` 사용 시의 잠재적인 성능 문제(탐색 시간)를 이해해야 합니다.
*   버킷 크기를 **디스크 블록(Disk Block)**과 연관 짓는 이유를 설명할 수 있어야 합니다.

2.  `John`이 `h()`에 의해 1번 버킷으로 매핑되어 해당 버킷의 첫 번째 슬롯에 삽입됩니다.
3.  `Smith`도 `h()`에 의해 1번 버킷으로 매핑되었고, `John`이 있는 슬롯은 이미 차 있으므로, 버킷 내의 다음 비어있는 슬롯(`empty`로 표시된 슬롯)에 `Smith`가 삽입됩니다.
4.  `Smith`가 삭제되면 해당 슬롯은 `deleted` 상태로 표시됩니다. (강의에서는 `deleted` 슬롯에 새 요소를 넣지 않는다고 가정합니다.)
5.  이제 `Mike`를 삽입하려 합니다. `Mike` 역시 `h()`에 의해 1번 버킷으로 매핑됩니다.
6.  1번 버킷을 순회하며 빈 슬롯을 찾습니다. `John` 슬롯은 차 있고, `deleted` 슬롯은 현재 규칙 상 새로운 요소를 삽입할 수 없습니다. 따라서 1번 버킷에는 `Mike`를 위한 공간이 없습니다.
7.  이 경우, `Mike`는 **오버플로우 버킷**으로 이동하여 저장됩니다. 슬라이드에서 `Mike`가 1번 버킷에 대한 "Collision" 및 "No slots" 상황으로 인해 `Overflow Buckets` 영역에 할당되는 것을 보여줍니다.

### 강의 맥락

교수님은 닫힌 해싱(Closed Hashing)의 두 가지 구현 방식 중 하나인 버킷 해싱(Bucket Hashing)을 설명합니다.

*   **버킷 해싱의 기본 아이디어**: "해시 테이블의 슬롯들을 버킷으로 묶습니다. 그리고 모든 버킷이 공유하는 무한 용량의 오버플로우 버킷이 유지됩니다." (transcript: "Bucket hashing is we group each of the hash table slots into the buckets. And there is an overflow bucket with infinite capacity shared by all buckets.")

(transcript: "So you can think of it as a separate data structure that contains all the elements that were not able to be inserted into the hash table. These elements are allocated to this overflow bucket. So it's kind of a cheat, right?")
*   **버킷 크기 설정**: 각 버킷에 몇 개의 슬롯을 그룹화할지는 설계 파라미터이며, 실제로는 디스크 블록(disk block)의 크기에 맞춰 설정하는 경우가 많다고 언급하셨습니다.
*   **`deleted` 상태의 슬롯 처리**: 교수님은 예시에서 `deleted`로 표시된 슬롯에 새로운 요소를 삽입하지 않는다고 가정하고 `Mike`가 오버플로우 버킷으로 가는 과정을 설명하셨습니다. 이 `deleted` 마크는 검색 과정에서 잘못된 종료를 방지하기 위함이었으나, 이에 대한 효율성 문제와 해결 방안에 대한 논의를 이어가셨습니다. ⭐`deleted` 슬롯에 새 레코드를 저장할 수 있는지, 그 이유는 무엇인지가 중요하게 다뤄지는 부분입니다.

### 시험 포인트

*   ⭐**버킷 해싱의 정의 및 충돌 처리 방식**: 해시 슬롯을 버킷으로 묶고, 버킷이 가득 찼을 때 오버플로우 버킷을 사용하는 원리를 이해해야 합니다.
*   ⭐**오버플로우 버킷의 역할**: 주 해시 테이블에 삽입되지 못한 요소들이 저장되는 보조 저장 공간임을 알아야 합니다.
*   ⭐**`deleted` 슬롯의 의미**: `deleted` 상태가 삽입 및 검색 작업에 어떤 영향을 미치는지, 특히 `deleted` 슬롯에 새로운 요소를 삽입하지 않는다는 가정이 왜 발생하는지에 대한 교수님의 설명을 이해하는 것이 중요합니다. (원래의 목적은 검색 시 잘못된 종료를 막기 위함이었으나, 효율성 문제가 발생할 수 있습니다.)
*   **버킷 크기 설정의 중요성**: 버킷 크기가 디스크 블록 단위로 설정될 수 있음을 기억하세요.

## Bucket Hashing

### 핵심 개념
Bucket Hashing은 클로즈드 해싱(Closed Hashing)의 한 구현 방식으로, 해시 테이블의 슬롯들을 여러 개의 **버킷(Buckets)**으로 그룹화하여 사용합니다. 각 버킷은 고정된 수의 슬롯을 가지며, 버킷 내의 모든 슬롯이 차면 **오버플로우 버킷(Overflow Buckets)**이라는 별도의 저장 공간에 데이터를 저장하여 해시 충돌을 처리합니다. 이 오버플로우 버킷은 모든 버킷에 의해 공유되며, 무한한 용량을 가질 수 있다고 가정합니다.

### 구체적 예시
슬라이드 그림은 `Insert(Mike, D)` 작업 후의 상태를 보여줍니다.
1.  초기 상태에서 `John`이 `버킷 1`의 첫 번째 슬롯에 삽입됩니다.
2.  이후 `Smith`가 `버킷 1`로 해싱되어 두 번째 슬롯에 삽입되었다고 가정합니다.
3.  `Smith`가 삭제되면, 해당 슬롯은 `deleted`로 표시됩니다. (그림의 `deleted` 슬롯)
4.  이제 `Mike`를 삽입하려고 할 때, `Mike` 역시 `버킷 1`로 해싱됩니다.
5.  `버킷 1`을 검사하면 `John`이 첫 번째 슬롯에 있고, 두 번째 슬롯은 `deleted` 상태입니다.
6.  강의에서는 `deleted`로 표시된 슬롯에는 새 요소를 추가하지 않는다고 가정하므로, `버킷 1`에는 `Mike`를 삽입할 공간이 없습니다.
7.  결국 `Mike`는 `버킷 1`에 들어가지 못하고, 그림과 같이 **오버플로우 버킷**에 할당됩니다.

### 강의 맥락
교수님은 클로즈드 해싱의 두 가지 구현 방식 중 하나로 버킷 해싱을 설명합니다.
*   **버킷의 정의**: 해시 테이블의 슬롯들을 그룹화한 것이며, 각 버킷은 마치 연결 리스트처럼 체인(chain)을 만들지 않고 데이터를 직접 저장합니다.
*   **오버플로우 버킷**: "무한한 용량을 가진 별도의 데이터 구조"로, 해시 테이블의 버킷에 더 이상 공간이 없을 때 사용됩니다. 이는 일종의 "꼼수(cheat)"라고 표현됩니다.
*   **`deleted` 상태의 역할**: `Smith`를 삭제한 후 해당 슬롯이 `deleted`로 표시된 이유는 ⭐**탐색(search) 과정에서 다른 키에 대한 검색이 잘못 종료되는 것을 방지하기 위함**입니다. 만약 `deleted`를 `empty`로 간주하면, 이후에 충돌로 인해 그 뒤에 삽입된 요소(이 예시에서는 `Mike`가 버킷에 삽입되었다고 가정할 경우)를 찾지 못할 수 있습니다.
*   **`deleted` 슬롯에 새 레코드 저장 불가**: 슬라이드 예시에서 `Mike`가 `deleted` 슬롯에 삽입되지 못하고 오버플로우 버킷으로 간 것은, 현재 시나리오에서 `deleted` 슬롯에 새 요소를 넣지 않는다는 가정을 따르기 때문입니다. 이는 실제로는 효율성 문제를 야기할 수 있으며, 교수님은 이에 대해 "너무 비효율적이지 않나?"라고 질문하며 디자인의 딜레마를 지적합니다.
*   **버킷 크기**: 실제 구현에서는 버킷 크기를 디스크 블록(disk block) 크기에 맞춰 할당하는 경우가 많다고 언급됩니다.

### 시험 포인트
*   ⭐**Bucket Hashing의 충돌 처리 방식**: 버킷 내 순차 삽입 및 오버플로우 버킷 사용.
*   ⭐**`deleted` 상태 슬롯의 필요성**: 검색 무결성을 유지하기 위함.
*   ⭐**`deleted` 상태 슬롯에 새 데이터 삽입 시 문제점 및 해결 방안(교수님 질문 기반)**: 삽입하지 않을 경우 오버플로우 버킷 사용으로 인한 성능 저하, 삽입할 경우 검색 로직 복잡화 가능성.
*   **Overflow Bucket의 역할**: 버킷이 가득 찼을 때 사용되는 예비 저장 공간.

**핵심 개념**
버킷 해싱(Bucket Hashing)은 닫힌 해싱(Closed Hashing)의 한 형태로, 해시 테이블의 슬롯들을 여러 개의 **버킷(buckets)**으로 그룹화하여 충돌을 처리하는 방식입니다. 해시 함수 $h(key)$는 키를 해시 테이블의 특정 버킷으로 매핑합니다. 동일한 버킷으로 해싱된 여러 항목은 해당 버킷 내의 빈 슬롯에 순차적으로 저장되며, 버킷이 가득 찬 경우 **오버플로우 버킷(overflow bucket)**이라는 별도의 저장 공간에 항목이 할당됩니다.

각 해시 테이블 슬롯은 다음 세 가지 상태 중 하나로 표시됩니다:
*   `empty`: 해당 슬롯이 비어있음.
*   `occupied`: 해당 슬롯에 데이터가 저장되어 있음.
*   `deleted`: 해당 슬롯에 이전에 데이터가 있었지만 현재는 삭제되었음을 나타냄.

**구체적 예시**
*   `h(John)`이 버킷 1을 반환하고 버킷 1이 비어있다면 `John`은 버킷 1의 첫 번째 슬롯에 삽입됩니다.
*   `h(Smith)`도 버킷 1을 반환하고 버킷 1의 첫 번째 슬롯에 `John`이 이미 있다면, `Smith`는 버킷 1의 다음 빈 슬롯에 삽입됩니다.
*   `Smith`가 삭제되면 해당 슬롯은 `deleted`로 표시됩니다.
*   `h(Mike)`가 버킷 1을 반환했으나 버킷 1의 모든 슬롯(예: `John`은 `occupied`, 다음 슬롯은 `deleted`)에 더 이상 빈 공간이 없다면, `Mike`는 오버플로우 버킷에 저장됩니다.

**강의 맥락**
*   버킷 해싱은 해시 테이블에 모든 요소를 직접 저장하며, 연결 리스트(Linked List) 형태의 체인(Chaining)을 사용하는 오픈 해싱(Open Hashing)과는 달리 추가 체인 메커니즘을 사용하지 않습니다.
*   교수님은 `deleted` 슬롯에 새 레코드를 저장할 수 있는지에 대한 질문을 던지며, 이 슬라이드의 예시에서는 이를 허용하지 않지만, 실제 구현에서는 가능하다고 언급하셨습니다.
*   `deleted` 상태의 주된 목적은 탐색 과정에서 잘못된 종료를 방지하기 위함입니다. 즉, 탐색 중 `deleted` 슬롯을 만나면, 해당 키와 동일한 해시 값을 가진 다른 요소가 뒤따르는 슬롯에 저장되어 있을 수 있으므로 탐색을 계속해야 함을 의미합니다.
*   `deleted` 슬롯을 재사용하지 않으면 해시 테이블의 효율성이 저하될 수 있으며, 이를 해결하기 위해 `deleted` 슬롯에 새 데이터를 삽입하고 상태를 `occupied`로 변경하는 등의 추가 규칙을 정의할 수 있습니다.
*   **오버플로우 버킷(Overflow Bucket)**은 원래 버킷에 저장할 수 없는 항목들을 보관하는 보조적인 자료구조이며, "치팅(cheating) 데이터 구조"라고 비유되었습니다. 이는 많은 데이터를 담을 수 있지만, 오버플로우 버킷에서 항목을 검색할 경우 탐색 시간이 크게 증가할 수 있다는 단점이 있습니다.

**시험 포인트**
*   ⭐버킷 해싱의 개념 및 충돌 처리 방식 (버킷 내 순차 저장, 오버플로우 버킷).
*   ⭐`empty`, `occupied`, `deleted` 세 가지 슬롯 상태의 의미와 이 중 `deleted` 상태가 탐색 및 삽입 연산에 미치는 영향.

## Bucket Hashing

### 핵심 개념
버킷 해싱(Bucket Hashing)은 해시 충돌(collision)을 해결하기 위한 **Closed Hashing (Open Addressing)** 방식의 한 구현체입니다. 해시 테이블의 슬롯들을 여러 개의 **버킷(Bucket)**으로 그룹화하여 사용합니다. 특정 키가 해시 함수 $h()$를 통해 매핑된 버킷이 가득 찰 경우, 데이터를 저장하기 위해 **오버플로우 버킷(Overflow Bucket)**이라는 별도의 저장 공간을 활용합니다. 이는 주로 **디스크에 저장되는 해시 테이블** 구현에 적합합니다.

### 구체적 예시
1.  **초기 상태**: 버킷 1의 슬롯들이 비어있습니다.
2.  **`John` 삽입**: `John`이 버킷 1로 해시되어 첫 번째 슬롯에 저장됩니다. (상태: `John`)
3.  **`Smith` 삽입**: `Smith`도 버킷 1로 해시됩니다. 첫 번째 슬롯은 `John`으로 이미 차 있으므로, 버킷 내의 다음 빈 슬롯(두 번째 슬롯)에 `Smith`가 저장됩니다. (상태: `John`, `Smith`)
4.  **`Smith` 삭제**: `Smith`를 삭제하면, 해당 슬롯은 `deleted` 상태로 표시됩니다. (`John`, `deleted`)
5.  **`Mike` 삽입**: `Mike` 역시 버킷 1로 해시됩니다. 버킷 1을 순회하면 `John`은 차 있고, 두 번째 슬롯은 `deleted` 상태입니다. 강의에서는 `deleted` 슬롯에 새 항목을 추가할 수 없다고 가정하여 버킷이 가득 찼다고 판단합니다. 이 경우 `Mike`는 **오버플로우 버킷**에 저장됩니다. (오버플로우 버킷에 `Mike` 추가)

### 강의 맥락
교수님은 닫힌 해싱(Closed Hashing)의 두 가지 구현 방식 중 하나로 버킷 해싱을 소개합니다.
*   **Closed Hashing**은 모든 요소를 해시 테이블 내에 직접 저장하며, 추가적인 체이닝 메커니즘이 없습니다. 각 슬롯은 `empty`, `occupied`, `deleted`의 세 가지 상태를 가집니다.
*   **버킷 해싱의 원리**: 해시 테이블의 슬롯들을 버킷으로 묶고, 모든 버킷이 공유하는 **무한 용량의 오버플로우 버킷**을 유지합니다. 이는 "치트 데이터 구조(cheating data structure)"처럼 해시 테이블에 맞지 않는 모든 요소를 저장할 수 있습니다.
*   **버킷 내 충돌 처리**: 새로운 항목이 삽입될 때, 해당 버킷 내의 빈 슬롯을 찾아 저장합니다. 버킷 내의 모든 슬롯이 차 있다면, 오버플로우 버킷으로 이동합니다.
*   **`deleted` 상태의 중요성**: 항목을 삭제할 때 슬롯을 `empty`가 아닌 `deleted`로 표시하는 이유는, 검색 과정에서 잘못된 종료를 방지하기 위함입니다. `deleted` 상태를 만나더라도 다음 슬롯에 다른 유효한 데이터가 있을 수 있으므로 계속 검색해야 합니다. (⭐ **시험 포인트**: `deleted` 상태를 사용하는 이유)
*   **단점**: `deleted` 슬롯에 새 항목을 삽입하지 못하면 버킷이 가득 찬 것으로 간주되어 오버플로우 버킷 사용이 잦아지고, 이는 검색 시 오버플로우 버킷까지 찾아야 하므로 시간이 많이 소요될 수 있습니다.
*   **버킷 크기**: 버킷의 크기는 일반적으로 **디스크 블록(disk block)**의 크기로 설정됩니다. 디스크 블록은 파일에 할당될 수 있는 가장 큰 연속적인 디스크 공간 단위를 의미하며, 하드웨어 사양에 따라 제한이 있습니다. 이는 디스크 I/O 효율성을 고려한 설계입니다.

### 시험 포인트
*   ⭐ **버킷 해싱의 정의 및 작동 방식**: 해시 충돌 시 버킷 내에서 빈 슬롯을 찾고, 버킷이 가득 차면 오버플로우 버킷을 사용하는 과정을 설명할 수 있어야 합니다.
*   ⭐ **`deleted` 상태의 목적**: 검색 과정에서 잘못된 종료를 막기 위함임을 이해해야 합니다.
*   ⭐ **버킷 크기의 설정**: 디스크 블록 크기로 설정하는 이유를 설명할 수 있어야 합니다.

**핵심 개념**
Rehashing (Open Addressing)은 클로즈드 해싱(Closed Hashing)의 한 종류로, 해시 충돌이 발생했을 때 보조적인 자료구조(예: 연결 리스트 또는 오버플로우 버킷)를 사용하지 않고 해시 테이블 내의 다른 빈 슬롯을 찾아 데이터를 저장하는 방법입니다. 해시 테이블의 각 슬롯은 `empty`, `occupied`, `deleted` 세 가지 상태 중 하나를 가질 수 있습니다.

**코드/수식 해설**
슬라이드에는 직접적인 코드나 수식은 없지만, 오픈 어드레싱의 핵심은 충돌 발생 시 다음 빈 슬롯을 탐색하는 'Probing (조사)' 과정입니다. 탐색할 다음 위치는 다음과 같은 일반적인 형태로 정의될 수 있습니다:
$$h(key, i) = (h_0(key) + p(i)) \pmod m$$
여기서:
*   $h_0(key)$는 원래 해시 함수를 통해 계산된 키의 초기 '홈 위치'입니다.
*   $p(i)$는 충돌이 발생했을 때 $i$번째 시도에서 추가적으로 탐색할 오프셋을 결정하는 'Probing 함수'입니다. $i=0$일 때는 $p(0)=0$이 되어 홈 위치를 나타냅니다.
*   $m$은 해시 테이블의 크기입니다.

교수님의 설명에서 언급된 가장 기본적인 Probing 함수(선형 조사)는 $p(i) = i$ 로 정의됩니다. 즉, 다음 위치는 $h_0(key) + 1$, $h_0(key) + 2$, ... 순으로 탐색합니다.

**구체적 예시**
슬라이드는 "John"이 이미 해시 테이블의 슬롯 1에 `occupied` 상태로 삽입되어 있는 초기 상태를 보여줍니다.
*   "Mike"를 삽입하려고 할 때, 해시 함수 `h()`가 `h(Mike)`를 슬롯 1로 매핑합니다.
*   그러나 슬롯 1은 이미 "John"으로 `occupied` 상태이므로 충돌이 발생합니다.
*   이때 오픈 어드레싱 방식은 Probing 과정을 통해 슬롯 1 다음의 빈 슬롯(예: 슬롯 2)을 찾아 "Mike"를 저장하게 됩니다.

**강의 맥락**
교수님은 클로즈드 해싱의 두 가지 구현 방식 중 하나로 Rehashing (Open Addressing)을 설명합니다. 이는 앞서 다룬 버킷 해싱(Bucket Hashing)과 대비되는 개념으로 강조됩니다.
*   버킷 해싱이 슬롯을 버킷으로 묶고 오버플로우 버킷을 사용하는 반면, 오픈 어드레싱은 추가적인 자료구조나 버킷 없이 모든 요소를 해시 테이블 내에 직접 저장합니다.
*   슬롯의 상태는 `empty`, `occupied`, `deleted`로 구분되며, 특히 `deleted` 상태를 유지하는 이유에 대한 논의는 향후 강의에서 더 깊이 다뤄질 예정입니다.
*   현재 슬라이드는 "John"이 슬롯 1에 삽입된 후 "Mike"를 삽입하려 할 때 발생할 충돌 상황을 제시하며, 오픈 어드레싱이 이 충돌을 어떻게 해결할지 (즉, 'Probing'을 통해 다음 빈 위치를 찾는 방식)에 대한 도입부 역할을 합니다.

**시험 포인트**
*   ⭐ **Rehashing (Open Addressing)**의 개념과 **Separate Chaining (Open Hashing)** 및 **Bucket Hashing**과의 차이점을 명확히 이해해야 합니다. 오픈 어드레싱은 모든 데이터를 해시 테이블 내에 직접 저장하는 방식입니다.
*   ⭐ 충돌 발생 시 **"Probing (조사)"**을 통해 빈 슬롯을 탐색하는 것이 오픈 어드레싱의 핵심입니다.
*   ⭐ 해시 테이블의 각 슬롯이 가질 수 있는 세 가지 상태(`empty`, `occupied`, `deleted`)를 기억해야 합니다. 특히 `deleted` 상태의 필요성을 이해하는 것이 중요합니다.

## Rehashing (Open Addressing)

### 핵심 개념
**Rehashing (Open Addressing)**은 해시 충돌(collision)이 발생했을 때 이를 해결하는 기법 중 하나입니다. Separate Chaining(Open Hashing)처럼 외부 체인(linked list)을 사용하지 않고, 모든 요소를 해시 테이블 내부에 직접 저장합니다. 충돌이 발생하면, **Probing (개방 주소 지정)**이라는 과정을 통해 해시 테이블 내의 다른 비어있는 슬롯을 찾아 데이터를 삽입합니다.

### 코드/수식 해설
충돌 발생 시, 다음 사용 가능한 슬롯을 찾기 위한 Probing 함수는 다음과 같이 정의될 수 있습니다.
$$h_i(x) = (h(x) + i) \pmod M$$
- $h_i(x)$: $i$번째 Probing 시도에서 얻어지는 해시 테이블 인덱스입니다.
- $h(x)$: 원래 키 $x$에 대한 초기 해시 함수 출력 값입니다.
- $i$: Probing 시도 횟수를 나타내는 정수입니다. $i=0$일 때 초기 해시 위치($h(x)$)를 시도하고, $i=1, 2, \ldots$ 순서로 다음 위치를 탐색합니다.
- $M$: 해시 테이블의 총 슬롯 개수(크기)입니다.
- $\pmod M$: 모듈로 연산으로, 계산된 인덱스가 해시 테이블의 유효한 범위($0$부터 $M-1$) 내에 있도록 보장합니다.

### 구체적 예시
예를 들어, `John`, `Mike`, `Smith` 모두 초기 해시 함수 $h(x)$에 의해 `slot 1`로 매핑된다고 가정합니다.
1. `John`은 `slot 1`에 성공적으로 삽입됩니다.
2. `Mike`를 삽입하려 할 때, $h(Mike)$의 결과는 `slot 1`이지만, `slot 1`은 이미 `John`으로 채워져 있어 충돌이 발생합니다.
3. 충돌을 해결하기 위해 위 Probing 함수를 사용합니다 (선형 Probing).
    - $i=0$: $h_0(Mike) = (h(Mike) + 0) \pmod M = 1$. `slot 1`은 Occupied(점유됨).
    - $i=1$: $h_1(Mike) = (h(Mike) + 1) \pmod M = (1 + 1) \pmod M = 2$. `slot 2`가 Empty(비어있음)하면 `Mike`는 `slot 2`에 삽입됩니다.

### 강의 맥락
교수님은 **Rehashing (Open Addressing)**을 설명하며, 이전에 다룬 **Bucket Hashing**과의 차이점을 명확히 합니다. Bucket Hashing이 버킷을 그룹화하고 오버플로우 버킷을 사용하는 반면, Rehashing은 추가적인 보조 저장 공간 없이 모든 데이터를 주 해시 테이블 내에 저장한다고 강조합니다. 그림에 나타난 것처럼 `John`이 `slot 1`에 이미 있을 때, `Mike`를 삽입하려고 하면 `slot 1`에서 **Collision(충돌)**이 발생합니다. 이때 **Probing**이라는 과정을 통해 **alternative slots(대체 슬롯)**을 찾아 `Mike`를 삽입합니다. 교수님은 $h_i(x) = (h(x) + i) \pmod M$ 수식을 통해 가장 기본적인 Probing 방식인 **선형 Probing**을 설명하며, $i$ 값이 증가함에 따라 충돌이 발생한 위치 다음부터 순차적으로 빈 슬롯을 탐색한다고 설명합니다. 이 방식은 충돌 발생 시 다음 인접한 빈 슬롯을 찾아 삽입하는 과정을 보여줍니다.

### 시험 포인트
- ⭐ **Rehashing (Open Addressing)의 정의**: 모든 요소를 해시 테이블에 직접 저장하며, 충돌 시 다른 빈 슬롯을 탐색하여 해결하는 기법입니다.
- ⭐ **Probing의 역할**: 해시 충돌 시 대체 슬롯을 찾는 과정입니다.
- ⭐ **선형 Probing의 수식과 동작 원리**: $h_i(x) = (h(x) + i) \pmod M$ 에서 $i$가 증가하며 순차적으로 다음 슬롯을 탐탐색하는 방식입니다.
- ⭐ **Open Hashing(Separate Chaining)과의 주요 차이점**: Open Addressing은 외부 체인을 사용하지 않고 모든 데이터를 해시 테이블 내에 직접 저장하는 것이 큰 특징입니다.

## Slide 40

**핵심 개념**:
Rehashing 또는 Open Addressing은 해시 충돌(Collision) 발생 시 데이터를 해시 테이블 내의 다른 빈 슬롯에 직접 저장하는 충돌 해결 기법입니다. 별도의 연결 리스트(Separate Chaining)나 오버플로 버킷(Overflow Bucket)을 사용하지 않고, 모든 요소를 주 해시 테이블 안에 유지합니다. 해시 테이블의 각 슬롯은 `empty`, `occupied`, `deleted` 세 가지 상태 중 하나를 가질 수 있습니다.

**코드/수식 해설**:
충돌이 발생했을 때 다음 빈 슬롯을 찾아 탐색하는 과정을 **Probing (탐색)**이라고 합니다. 가장 단순한 탐색 방법 중 하나인 **선형 탐색(Linear Probing)**은 다음과 같이 정의됩니다:
$$h_i(x) = (h(x) + i) \pmod m$$
여기서 $h(x)$는 원래 해시 함수의 출력(홈 위치), $i$는 탐색 횟수를 나타내는 인덱스(최초 시도는 $i=0$), 그리고 $m$은 해시 테이블의 크기입니다. $i$가 $0, 1, 2, \dots$로 증가함에 따라 원래 해시된 위치($h(x)$)부터 순차적으로 다음 슬롯을 확인합니다.

**구체적 예시**:
1.  **`John` 삽입**: 해시 함수 `h(John)`이 1을 반환한다고 가정하면, `John`은 인덱스 1에 저장됩니다. (현재 슬라이드 그림의 상태)
2.  **`Mike` 삽입**: 해시 함수 `h(Mike)`도 1을 반환한다고 가정합니다. 인덱스 1은 `John`으로 이미 채워져 있으므로 충돌이 발생합니다. 선형 탐색($i=1$)을 통해 다음 슬롯인 인덱스 2를 확인하고, 인덱스 2가 비어있으므로 `Mike`를 인덱스 2에 저장합니다. (현재 슬라이드 그림의 상태)
3.  **`Smith` 삽입**: 해시 함수 `h(Smith)` 역시 1을 반환한다고 가정합니다. 인덱스 1(`John`)과 2(`Mike`) 모두 충돌이 발생하므로, 선형 탐색($i=2$)을 통해 다음 슬롯인 인덱스 3을 확인하고 `Smith`를 인덱스 3에 저장합니다.
4.  **`Mike` 삭제**: `Mike`를 삭제하려면 먼저 `h(Mike)`인 인덱스 1부터 탐색합니다. 인덱스 1에는 `John`이 있으므로 계속 탐색($i=1$)하여 인덱스 2에서 `Mike`를 찾습니다. `Mike`가 있는 슬롯을 찾아 데이터를 삭제하고, 해당 슬롯은 `deleted` 상태로 표시합니다. (이 `deleted` 표시는 이후 탐색 시 해당 위치가 비었지만 탐색을 멈추지 않고 계속 진행해야 함을 알려줍니다.)
5.  **`Mary` 삽입**: `h(Mary)`가 `M-1` (해시 테이블의 마지막 인덱스)을 반환한다고 가정합니다. `M-1` 슬롯이 비어있으므로 충돌 없이 `Mary`는 인덱스 `M-1`에 저장됩니다.

**강의 맥락**:
강의는 Rehash가 **Open Addressing**이라고도 불리며, 이전 강의에서 다룬 Bucket Hashing과 달리 추가적인 오버플로 버킷을 사용하지 않고 모든 데이터를 해시 테이블 내에 직접 저장하는 방식임을 설명합니다. 충돌 발생 시 빈 슬롯을 찾는 과정을 **Probing(탐색)**이라고 부르며, 가장 간단한 탐색 함수인 선형 탐색(`h(x) + i`)을 소개합니다. 슬라이드 그림에서 `John`이 인덱스 1에, `Mike`가 인덱스 2에 저장된 것은 `Mike`가 원래 `h(Mike)`=1로 해시되었으나 `John`과의 충돌로 인해 선형 탐색을 통해 다음 빈 슬롯인 인덱스 2로 이동한 결과임을 설명합니다.

이어지는 `Insert(Smith, D)`, `Delete(Mike, D)`, `Insert(Mary, D)` 연산 시나리오를 통해 Open Addressing의 동작 방식을 상세히 설명합니다. 특히 `Mike`를 삭제할 때, `h(Mike)`가 1이므로 인덱스 1부터 탐색을 시작하여 `John`을 지나 `Mike`를 찾아 삭제하게 됨을 강조합니다. 이 과정에서 삭제된 슬롯을 `deleted`로 표시하는 것이 이후의 탐색에서 잘못된 종료를 방지하는 데 중요함도 언급합니다.

**시험 포인트**:
*   ⭐ **Open Addressing의 개념**: 해시 테이블 내에서 직접 충돌을 처리하고, 연결 리스트나 오버플로 버킷을 사용하지 않는다는 점.
*   ⭐ **Probing(탐색)**의 역할: 충돌 발생 시 해시 테이블 내에서 대체 저장 위치를 찾는 과정.
*   ⭐ **선형 탐색(Linear Probing)**의 정의 및 동작 방식: $(h(x) + i) \pmod m$
*   ⭐ Open Addressing에서 **'deleted' 상태**가 필요한 이유 (탐색 효율성을 위해 삭제된 슬롯을 `empty`와 구별하는 목적).

## Rehashing (Open Addressing)

**핵심 개념**:
리해싱(Rehashing)은 오픈 어드레싱(Open Addressing)이라고도 불리는 해시 충돌(Collision) 해결 기법 중 하나입니다. 오픈 어드레싱에서는 모든 요소를 해시 테이블 내부에 직접 저장하며, 충돌 발생 시 비어있는 다른 슬롯을 찾아 데이터를 삽입합니다. 이 방식은 체인(연결 리스트)을 사용하는 오픈 해싱(Separate Chaining)과 달리 보조적인 자료구조(예: 오버플로우 버킷)를 사용하지 않습니다. 각 슬롯은 `empty`, `occupied`, `deleted` 세 가지 상태 중 하나로 표시됩니다.

**코드/수식 해설**:
충돌이 발생했을 때 대체 슬롯을 찾는 과정을 **프로빙(Probing)**이라고 합니다. 일반적인 프로빙 함수는 다음과 같이 정의될 수 있습니다:
$$h(key, i) = (h_0(key) + p(i)) \pmod M$$
여기서 $h_0(key)$는 원래의 해시 함수 출력 값(Home Position)이고, $p(i)$는 $i$번째 시도에 대한 프로빙 함수입니다. $M$은 해시 테이블의 크기입니다.

가장 단순한 프로빙 함수인 **선형 프로빙(Linear Probing)**의 경우, $p(i) = i$ 로 정의됩니다.
$$h(key, i) = (h_0(key) + i) \pmod M$$
$i=0$일 때는 원래 해시 값 $h_0(key)$를 시도하고, $i=1$일 때는 $h_0(key)+1$을, $i=2$일 때는 $h_0(key)+2$를 시도하는 식입니다.

**구체적 예시**:
슬라이드는 `Insert(Smith, D)`, `Delete(Mike, D)`, `Insert(Mary, D)` 작업 이후의 해시 테이블 상태를 보여줍니다.

*   `John`은 해시 함수에 의해 인덱스 1에 할당되었습니다.
*   `Smith`를 삽입하려 할 때, 만약 `Smith`의 원래 해시 값도 1이었다면 충돌이 발생했을 것입니다. 슬라이드에서는 `John`이 1번 슬롯에 있고, `Smith`는 3번 슬롯에 있습니다. 이는 `Smith`가 원래 해시 함수에 의해 인덱스 1로 매핑되었지만, 1번 슬롯이 `John`으로 이미 차 있어서 프로빙을 통해 3번 슬롯을 찾았음을 암시합니다.
*   `Mike`가 인덱스 2에 있었다가 `Delete(Mike, D)` 작업으로 인해 해당 슬롯이 `deleted` 상태로 변경되었습니다.
*   `Mary`는 해시 테이블의 `M-1` 인덱스에 저장되어 있습니다.

`deleted` 상태는 특정 요소가 삭제되었음을 나타내지만, 빈(empty) 슬롯과는 다르게 처리됩니다. 그 이유는 검색 과정에서 `deleted` 슬롯을 만나더라도 검색을 중단하지 않고 계속해서 프로빙해야 하기 때문입니다. 만약 `deleted` 슬롯을 `empty`로 간주하고 검색을 중단하면, 이후에 삽입된 요소(예: 충돌로 인해 원래 위치보다 뒤에 저장된 요소)를 찾지 못할 수 있습니다.

**강의 맥락**:
교수님은 리해싱(Rehashing) 또는 오픈 어드레싱(Open Addressing)이 해시 충돌을 처리하는 방법임을 설명하며, 이는 이전의 버킷 해싱(Bucket Hashing)과 달리 추가적인 오버플로우 버킷이나 버킷 그룹화를 사용하지 않는다고 강조합니다. 대신, 충돌이 발생하면 **프로빙(Probing)** 과정을 통해 해시 테이블 내의 다른 빈 슬롯을 찾아 데이터를 삽입한다고 설명합니다.

슬라이드의 그림은 `John`, `Smith`, `Mary`가 삽입되고 `Mike`가 삭제된 후의 해시 테이블 상태를 보여주며, 특히 인덱스 2가 `deleted`로 표시된 것이 중요합니다. 교수님은 `Mike`를 삭제할 때의 과정을 예로 들면서, 만약 `Mike`의 원래 해시 함수 출력값이 1이었다면, 인덱스 1에 `John`이 있으므로 프로빙을 통해 `Mike`를 찾아 삭제해야 한다고 설명합니다. 또한, `deleted` 슬롯의 역할에 대해 "삭제된(deleted) 슬롯에 새로운 데이터를 저장할 수 있는가?"라는 질문을 던지며, `deleted` 마크는 다른 키에 대한 검색 프로세스가 잘못 종료되지 않도록 보장하기 위함이었다고 언급합니다.

**시험 포인트**:
*   ⭐ **오픈 어드레싱(Open Addressing)**의 개념과 해시 충돌 해결 방식 (추가 보조 자료구조 없이 해시 테이블 내에서 해결).
*   ⭐ **`empty`, `occupied`, `deleted`** 세 가지 슬롯 상태의 의미와 각 상태가 삽입, 삭제, 검색 시 어떻게 다르게 처리되는지 이해하는 것. 특히 `deleted` 상태의 필요성(검색 중단 방지)을 설명할 수 있어야 합니다.
*   ⭐ **프로빙(Probing)**의 개념과 종류 (선형 프로빙, 이차 프로빙, 이중 해싱 등) 및 각 방식의 장단점 (특히 클러스터링 문제).

## Slide 42

**핵심 개념**
**리해싱(Rehashing)** 또는 **오픈 어드레싱(Open Addressing)**은 클로즈드 해싱(Closed Hashing)의 충돌 해결 기법 중 하나입니다. 이 방법은 별도의 연결 리스트(체이닝)나 오버플로우 버킷(Bucket Hashing) 없이, 충돌이 발생했을 때 해시 테이블 내에서 다른 빈 슬롯을 찾아 데이터를 직접 저장합니다. 해시 테이블의 각 슬롯은 `empty`, `occupied`, `deleted` 세 가지 상태 중 하나로 표시됩니다.

**코드/수식 해설**
리해싱에서 충돌 발생 시 다음 탐 탐색할 위치는 **탐사 함수(probe function)** $p(i)$를 사용하여 결정됩니다. $i$는 탐사 시도 횟수를 나타내며, $0$부터 시작합니다.
$$h_i(x) = (h(x) + p(i)) \pmod M$$
여기서:
*   $h_i(x)$는 $i$번째 탐사 시도에 대한 해시 테이블 인덱스입니다.
*   $h(x)$는 원래 키 $x$에 대한 초기 해시 함수 출력값입니다.
*   $p(i)$는 탐사 함수이며, $i$에 따라 달라지는 값을 반환합니다.
*   $M$은 해시 테이블의 크기입니다.

**구체적 예시**
1.  `John`을 삽입하면 해시 함수 $h(.)$에 의해 인덱스 1에 저장됩니다. (상태: `occupied`)
2.  이후 `Mike`를 삽입하는데, $h(Mike)$ 역시 인덱스 1을 반환하여 충돌이 발생합니다.
3.  리해싱에서는 `Mike`를 인덱스 1에 바로 저장하지 않고, 탐사 함수 $p(i)$를 사용하여 다음 빈 슬롯을 찾습니다. 예를 들어, $p(1)$을 적용하여 인덱스 2가 비어있다면 `Mike`를 인덱스 2에 저장합니다.
4.  만약 `Mike`가 인덱스 2에 저장된 후 삭제된다면, 인덱스 2는 `deleted` 상태로 표시됩니다. 이는 나중에 `Smith`와 같이 인덱스 1에서 충돌하여 인덱스 3으로 탐사된 요소를 검색할 때, `deleted` 슬롯을 건너뛰고 계속 탐색해야 함을 의미합니다.

**강의 맥락**
교수님은 클로즈드 해싱의 한 종류인 리해싱 또는 오픈 어드레싱을 설명하며, 이전 버킷 해싱과의 차이점을 강조합니다. 버킷 해싱이 충돌 시 동일 버킷 내의 빈 슬롯을 찾거나 오버플로우 버킷을 사용하는 반면, 리해싱은 추가 구조 없이 해시 테이블 내에서 **탐사(Probing)** 과정을 통해 다음 빈 슬롯을 찾습니다.

*   `John`이 인덱스 1에 할당되고, `Mike`도 같은 인덱스 1로 해시되어 충돌이 발생합니다. 이때 `probe function`을 사용하여 다음 위치를 탐색합니다. (예: `Mike`는 인덱스 2로 이동).
*   `Smith` 역시 인덱스 1로 해시되어 충돌하면, `probe function`을 통해 인덱스 3으로 이동하여 저장될 수 있습니다.
*   `deleted` 상태의 슬롯(`deleted`로 표시된 인덱스 2)은 중요한 역할을 합니다. 만약 이 슬롯이 단순히 `empty`로 표시된다면, `Smith`를 검색할 때 $h(Smith)=1$이므로 인덱스 1을 확인하고, 그 다음 인덱스 2를 확인했을 때 `empty`라면 `Smith`가 없다고 판단하고 검색을 중단할 수 있습니다. 그러나 `deleted`로 표시하면, 실제로 `Smith`가 인덱스 3에 있을 수 있으므로 검색을 계속해야 함을 의미합니다. 이는 삭제로 인해 검색 경로가 끊기는 것을 방지합니다.

**시험 포인트**
*   ⭐ **오픈 어드레싱의 개념**: 충돌 발생 시 해시 테이블 내의 다른 슬롯을 찾는 방법임을 이해해야 합니다.
*   ⭐ **탐사 함수($p(i)$)의 역할**: 충돌 시 탐사(probing) 과정을 통해 다음 위치를 결정하는 함수의 중요성을 파악해야 합니다.
*   ⭐ **`deleted` 상태의 필요성**: 삭제된 레코드 슬롯을 `empty`가 아닌 `deleted`로 표시하는 이유를 정확히 설명할 수 있어야 합니다. (특히 검색 과정에서 발생할 수 있는 문제와 관련하여)

## Slide 43

### 핵심 개념

**선형 탐사 (Linear Probing)**는 해시 충돌(collision)이 발생했을 때 충돌된 위치부터 순차적으로(선형적으로) 비어있는 다음 슬롯을 찾아 데이터를 삽입하는 개방 주소 지정(open addressing) 방식의 한 종류입니다. 가장 단순한 탐사 함수를 사용하며, 이는 **일차 군집화(Primary Clustering)**라는 심각한 단점을 야기합니다.

### 코드/수식 해설

선형 탐사에서 사용하는 탐사 함수 `p(i)`는 탐사 횟수 `i`에 대한 선형 함수이며, 일반적으로 `p(i) = i`로 정의됩니다. 이를 이용한 전체 해시 함수 `h_i(x)`는 다음과 같습니다:

$$ h_i(x) = (h(x) + i) \pmod M $$

*   $\boldsymbol{h(x)}$: 원래의 해시 함수가 키 $\boldsymbol{x}$에 대해 반환하는 최초 해시 값 (홈 위치).
*   $\boldsymbol{i}$: 탐사 횟수 (probe count). 0부터 시작하여 충돌이 발생할 때마다 1씩 증가합니다.
    *   $\boldsymbol{i=0}$일 때: $h_0(x) = h(x) \pmod M$ (첫 번째 시도, 홈 위치 확인)
    *   $\boldsymbol{i=1}$일 때: $h_1(x) = (h(x) + 1) \pmod M$ (두 번째 시도, 다음 슬롯 확인)
    *   $\boldsymbol{i=2}$일 때: $h_2(x) = (h(x) + 2) \pmod M$ (세 번째 시도, 그 다음 슬롯 확인)
    *   ...와 같이 순차적으로 인덱스를 증가시키며 탐사합니다.
*   $\boldsymbol{M}$: 해시 테이블의 크기 (슬롯의 총 개수). `% M` (모듈로 연산)을 통해 해시 테이블 인덱스 범위를 벗어나지 않도록 합니다.

### 강의 맥락

교수님께서는 해시 충돌 처리 방식 중 '폐쇄 주소 지정(Closed Hashing)' 또는 '개방 주소 지정(Open Addressing)' 방식에 대한 설명의 일환으로 선형 탐사를 소개하셨습니다. 충돌이 발생했을 때 대체 슬롯을 찾는 과정을 "Proving Process"라고 설명하시면서, `h_i(x) = (h(x) + i) mod M` 수식을 통해 `i`가 탐사 횟수(몇 번째 시도인지)를 나타내며, `hx`는 원래 해시 함수가 반환하는 값, `M`은 해시 테이블의 크기임을 강조하셨습니다.

선형 탐사는 가장 "naive(순진한)"한 탐사 함수 설계이며, 충돌 시 바로 다음 위치를 확인하는 방식입니다.

하지만 교수님은 이러한 선형 탐사의 명백한 단점으로 ⭐**일차 군집화(Primary Clustering)**를 지적하셨습니다.

*   **발생 원인**: 해시 함수 값이 비슷하거나 심지어 같은 아이템들이 결국 해시 테이블의 인접한 위치에 뭉치게(클러스터링) 됩니다.
*   **문제점**: 일단 아이템들이 한 번 뭉치기 시작하면, 새로 삽입되는 아이템들 또한 이 뭉쳐있는 곳에 삽입될 가능성이 높아지며, 이 클러스터가 계속해서 길어지게 됩니다. 이는 "long proving sequence"로 이어져 삽입, 삭제, 검색 시 긴 탐사 시간 (많은 충돌 처리)을 필요로 하게 됩니다. 즉, 선형 탐사는 `O(1)`이라는 평균 시간 복잡도의 장점을 상쇄시킬 수 있는 심각한 비효율성을 초래할 수 있습니다.

## Slide 44

**핵심 개념**

*   **Linear Probing with Skipping**: 기존 선형 탐사(linear probing) 방식에서 충돌 발생 시 다음 빈 슬롯을 탐색할 때, 단순히 $+1$ 하는 대신 상수 $c$ 만큼 '건너뛰면서(skipping)' 탐색하는 방법입니다.
*   **상수 $c$ 의 조건**: 모든 슬롯을 방문하기 위해서는 상수 $c$ 와 해시 테이블 크기 $M$ 이 서로소(relatively prime)여야 합니다.
*   **Primary Clustering (일차 군집화)**: 상수 $c$ 를 사용해도 여전히 발생하는 문제로, 서로 다른 초기 해시 값을 가진 키들이 유사한 탐사 시퀀스를 공유하며 군집을 형성하는 현상입니다. 이는 효율적인 탐색을 방해합니다.

**코드/수식 해설**

탐사 함수 $h_i(x)$는 다음과 같이 정의됩니다:

$$h_i(x) = (h(x) + (c \times i)) \pmod M$$

*   $h(x)$: 키 $x$ 에 대한 초기 해시 함수 결과 (홈 위치).
*   $c$: 건너뛸 상수 값 ($c \ge 1$).
*   $i$: 탐사 시도 횟수 (첫 시도는 $i=0$, 충돌 시 $i=1, 2, \ldots$).
*   $M$: 해시 테이블의 크기.
*   `mod M`: 해시 테이블 인덱스 범위를 벗어나지 않도록 하는 나머지 연산.

교수님은 "$c$ 가 $i$ 에 곱해지며, 이는 다음 위치 탐색 시 '건너뛰는(skipping)' 정도를 나타냅니다. $c=1$ 이면 이전의 선형 탐사와 동일합니다." 라고 설명하셨습니다.

**구체적 예시**

상수 $c=2$ 이고 해시 테이블 크기 $M$ 이 충분히 크다고 가정할 때:

*   키 $k_1$ 의 초기 해시 값 $h(k_1) = 3$ 인 경우, 탐사 시퀀스는 $3, (3+2)\%M=5, (5+2)\%M=7, (7+2)\%M=9, \dots$ 와 같이 전개됩니다.
*   키 $k_2$ 의 초기 해시 값 $h(k_2) = 5$ 인 경우, 탐사 시퀀스는 $5, (5+2)\%M=7, (7+2)\%M=9, \dots$ 와 같이 전개됩니다.

두 키의 탐사 시퀀스는 $5, 7, 9, \dots$ 에서 겹치게 됩니다. 교수님은 "이러한 공유된 탐사 시퀀스 덩어리(shared chunks of the proving sequence)는 문제가 될 수 있으며, 해시 테이블 연산의 효율성을 떨어뜨립니다. $k_1$ 과 $k_2$ 의 탐사 시퀀스가 연결되어 군집화에 기여합니다." 라고 강조하셨습니다.

**강의 맥락**

이 슬라이드는 개방 주소법(Open Addressing)의 한 형태인 선형 탐사(Linear Probing)의 개선된 버전을 설명합니다. 교수님은 이전 슬라이드에서 `h_ix = (hx + i) mod M` 형태의 가장 단순한 선형 탐사를 설명한 후, 그 문제점인 "일차 군집화(primary clustering)"를 해결하기 위한 방법으로 상수 $c$ 를 곱하여 건너뛰는 방식을 도입합니다.

*   교수님은 "탐사 시퀀스에서 다음 위치를 건너뛸(skipping) 수 있는 양을 나타내는 상수 $c$ 를 곱하는 것이 가장 단순한 해결책입니다. 이 $c$ 값은 $1$ 이상이어야 하며, 보통 $1$ 보다 크게 설정합니다. 만약 $c=1$ 이라면 이전의 선형 탐사와 같습니다." 라며 수식에 사용된 $c$ 의 역할을 설명하셨습니다.
*   ⭐ **시험 포인트**: "이 상수 $c$ 는 해시 테이블의 전체 크기 $M$ 과 서로소(relatively prime)여야 합니다. 이는 홈 위치로 되돌아가기 전에 해시 테이블의 모든 슬롯을 방문하기 위함입니다." 라며 $c$ 와 $M$ 의 관계의 중요성을 강조하셨습니다. 또한 "만약 $M=30$ 이고 $c=15$ 라면, $0, 15, 0, 15$ 와 같이 동일한 위치만 계속 재방문하여 모든 슬롯을 탐색할 수 없게 됩니다."라는 예시를 들어 이 조건의 필요성을 부연하셨습니다.
*   교수님은 "하지만 여전히 군집이 남을 수 있습니다. $c$ 를 사용해도 여전히 일부 군집이 남는 경우가 발생합니다." 라며 Primary Clustering 이 여전히 문제임을 지적하셨습니다. 위에 제시된 $h(k_1)=3$ 과 $h(k_2)=5$ 의 예시를 통해 "두 키의 탐사 시퀀스에 $7, 9, 11, 13, \dots$ 와 같은 공통된 부분이 생기는 것을 볼 수 있습니다. 이러한 공유된 탐사 시퀀스 덩어리는 문제가 될 수 있습니다. $k_1$ 과 $k_2$ 의 탐사 시퀀스가 연결되어 군집화에 기여합니다." 라고 설명하며, 이는 비효율적인 해시 테이블 연산을 초래한다고 강조했습니다.

**시험 포인트**

*   ⭐ **선형 탐사에서 상수 $c$ 의 역할과 탐사 함수($h_i(x)$) 정의를 정확히 이해해야 합니다.**
*   ⭐ **상수 $c$ 와 해시 테이블 크기 $M$ 이 서로소여야 하는 이유를 설명할 수 있어야 합니다.** (모든 슬롯을 방문하기 위함)
*   ⭐ **Primary Clustering (일차 군집화) 의 개념을 이해하고, 상수 $c$ 를 사용하더라도 왜 이 문제가 여전히 발생하는지 예시를 들어 설명할 수 있어야 합니다.**

## Slide 45

### 핵심 개념

해시 테이블에서 선형 탐사(Linear Probing) 방식 사용 시, 해시 값이 유사하거나 같은 키들이 특정 영역에 집중되어 탐사 길이가 길어지는 현상을 **Primary Clustering(주 클러스터링)**이라고 합니다. 이 슬라이드는 이러한 Primary Clustering 문제를 해결하기 위한 방법을 논의합니다.

### 코드/수식 해설

탐사(Probing) 함수는 `h_i(x) = (h(x) + P_i) mod m` 형태로 정의되며, 여기서 $h(x)$는 초기 해시 값, $P_i$는 탐사 함수($i$는 시도 횟수), $m$은 해시 테이블 크기입니다.

*   **Linear Probing (선형 탐사)**: $P_i = i$ 형태로, 충돌 발생 시 바로 다음 슬롯을 순차적으로 탐사하는 방식입니다. 이 방식은 Primary Clustering을 유발합니다.
*   **Pseudo-random Probing (준-랜덤 탐사)**: $P_i$를 미리 정의된 랜덤 순열($d_i$)로 사용하여 탐사 간격을 불규칙하게 만듭니다.
*   **Quadratic Probing (2차 탐사)**: $P_i$를 $C_1 i^2 + C_2 i + C_3$와 같은 2차 함수 형태로 정의하여 탐사 간격을 늘립니다.

### 구체적 예시

*   **순수 랜덤 Probing의 문제점**: 만약 충돌이 발생했을 때 다음 탐사 위치를 완전히 무작위로 선택한다면, 나중에 특정 키를 검색할 때 어떤 경로로 탐사해야 할지 알 수 없게 됩니다. 삽입 시 사용된 랜덤 탐사 순서를 저장해두지 않으면, 검색 시 전체 해시 테이블을 순회해야 하는 비효율적인 상황이 발생합니다.

### 강의 맥락

교수님은 Primary Clustering이 발생하는 이유로 키들이 해시 테이블 내 유사한 영역에 집중되는 현상(primary clustering)을 지적했습니다. 이는 `h(x) + c * i`와 같이 일정한 간격으로 탐사할 때 특히 문제가 됩니다.

*   교수님은 "탐사를 완전히 랜덤하게 할 수 있는가?"라는 질문을 던지며, 학생의 답변을 통해 순수 랜덤 탐사가 **탐색 과정에서 비효율적**이라는 점(이전 탐사 기록이 없으면 어디를 찾아야 할지 알 수 없으므로 전체 테이블을 검색해야 함)을 강조했습니다.
*   이러한 순수 랜덤 탐사의 문제점을 해결하기 위한 대안으로 **Pseudo-random Probing**과 **Quadratic Probing** 두 가지 방법을 제시했습니다.

### 시험 포인트

*   ⭐ **Primary Clustering**의 개념과 문제점을 정확히 설명할 수 있어야 합니다.
*   ⭐ **순수 랜덤 Probing** 방식이 삽입 시에는 클러스터링을 피할 수 있지만, **검색(Search) 시에 왜 치명적인 문제점**을 가지는지 그 이유를 설명할 수 있어야 합니다.
*   ⭐ Primary Clustering을 피하기 위한 **두 가지 주요 탐사 방법(Pseudo-random Probing, Quadratic Probing)**의 명칭과 각 방법의 기본적인 아이디어를 알아두세요. (자세한 수식은 다음 슬라이드에서 다뤄질 예정)

## Slide 46

### 핵심 개념
의사-랜덤 프로빙(Pseudo-Random Probing)은 해시 충돌(collision) 발생 시 다음 탐색할 슬롯의 위치를 결정하는 방법 중 하나입니다. 기존 선형 프로빙(Linear Probing)의 문제점인 1차 군집화(Primary Clustering)를 피하기 위해 도입되었습니다. 이는 다음 탐색 위치를 `i`에 대한 단순 선형 함수가 아닌, 미리 정의된 '랜덤 순열'을 이용하여 결정하는 방식입니다.

### 코드/수식 해설
`i`-번째 탐색 슬롯의 위치는 다음 수식으로 결정됩니다:
$$
h_i(x) = (h(x) + d_i) \pmod M
$$
여기서:
*   $h(x)$는 원본 해시 함수가 키 $x$에 대해 반환하는 초기 해시 값(홈 위치)입니다.
*   $d_i$는 $1, 2, \ldots, M-1$ 범위의 정수들로 이루어진 **랜덤 순열(random permutation)**의 $i$-번째 값입니다.
*   $M$은 해시 테이블의 크기입니다.
*   `mod M` 연산은 결과가 $0$부터 $M-1$ 범위 내에 있도록 합니다.

이 방법은 매번 임의의 숫자를 생성하는 '순수 랜덤 프로빙'과 달리, `d_1, d_2, ..., d_{M-1}`과 같은 **고정된(fixed) 랜덤 순열**을 사용합니다.

### 구체적 예시
이 슬라이드에서는 직접적인 예시가 제시되지 않지만, 이러한 랜덤 순열을 생성하는 한 가지 효과적인 방법으로 "shift-register sequence"가 있습니다. (자세한 내용은 다음 슬라이드에서 다룹니다.)

### 강의 맥락
교수님은 순수하게 무작위로 다음 탐색 위치를 결정하는 방식이 검색 시 문제가 된다고 설명합니다. "나중에 검색할 때, 무작위 숫자 생성 이력이 기록되지 않으면 그 요소를 더 이상 찾을 방법이 없기 때문입니다. 어디로 가야 할지 모르기 때문에 전체 해시 테이블을 검색해야 하는데, 이는 불가능합니다." 이러한 문제점을 해결하기 위해 "랜덤하지만 특정 규칙에 기반한" 의사-랜덤 프로빙을 도입합니다.

교수님은 $d_i$가 $1$부터 $M-1$까지의 정수들을 무작위로 섞은 순열이며, 이는 한번 생성되면 **고정되어 저장**된다는 점을 강조합니다. 이렇게 고정된 순열을 사용함으로써 삽입(insertion)과 검색(search) 모두 동일한 순서로 다음 위치를 탐색할 수 있어 순수 랜덤 프로빙의 검색 문제를 해결합니다. 이러한 랜덤 순열을 생성하는 방법 중 하나로 "shift-register sequence"를 언급하며, 이를 통해 확률 분포에 기반한 샘플링 없이도 난수를 생성할 수 있다고 설명합니다.

### 시험 포인트
*   ⭐ **의사-랜덤 프로빙의 목적**: 1차 군집화(Primary Clustering)를 피하면서도 검색이 가능하도록 함.
*   ⭐ **$d_i$의 특징**: $1$부터 $M-1$까지의 정수들의 **고정된(fixed) 랜덤 순열**이며, 삽입과 검색 시 모두 동일하게 사용되어야 합니다.
*   **순수 랜덤 프로빙과의 차이점**: 순수 랜덤 프로빙은 검색 불가능성이 크지만, 의사-랜덤 프로빙은 고정된 순열을 사용하여 검색 가능성을 유지합니다.
*   **랜덤 순열 생성 방법**: `shift-register sequence`가 하나의 예시입니다.

## Slide 47

**핵심 개념**
Shift-Register Sequence는 해시 테이블의 충돌 처리 방식 중 하나인 `Open Addressing`에서 `Pseudo-Random Probing`을 구현하기 위한 방법입니다. 이는 탐색 위치를 무작위처럼 보이지만 예측 가능한 순서로 생성하여 `Secondary Clustering` 문제를 완화하고, 동시에 검색 시에도 동일한 순서를 재현하여 원소를 찾을 수 있도록 합니다. $M$은 해시 테이블의 크기(2의 거듭제곱)이고, $k$는 상수이며, $d_1$은 시작 값입니다.

**코드/수식 해설**

Shift-Register Sequence 알고리즘은 다음과 같습니다:

주어진 값:
*   $M$: 해시 테이블의 크기 (2의 거듭제곱)
*   $k$: 상수 ($1 \le k \le M-1$)

수열 생성:
1.  **시작 값 설정**: $d_1$을 $1 \le d_1 \le M-1$ 범위 내의 임의의 숫자로 설정합니다.
2.  **연속적인 숫자 ($d_2, d_3, d_4, \dots$) 생성**: 이전 숫자 $d_{i-1}$를 기반으로 $d_i$를 계산합니다.

    ```
    current_d = d_{i-1}
    next_d_temp = current_d * 2

    if next_d_temp >= M:
        next_d_temp = next_d_temp - M
        next_d = next_d_temp XOR k  // 'XOR'는 bitwise modulo-2 sum을 의미
    else:
        next_d = next_d_temp
    
    d_i = next_d
    ```

**구체적 예시**
교수님의 강의 예시 ($M=8$, $k=3$, $d_1=5$)를 따릅니다.
*   $M = 8$ (2의 거듭제곱), $k=3$ (이진수로 `011`)
*   $d_1 = 5$ (이진수로 `101`)

1.  **$d_2$ 생성 (from $d_1=5$)**:
    *   이전 숫자 2배: $5 \times 2 = 10$.
    *   결과가 $M$ 이상($10 \ge 8$): $10 - 8 = 2$ (이진수 `010`).
    *   결과와 $k$를 XOR: $2 \oplus 3$ (`010` $\oplus$ `011`) $= 1$ (이진수 `001`).
    *   따라서 $d_2 = 1$.

2.  **$d_3$ 생성 (from $d_2=1$)**:
    *   이전 숫자 2배: $1 \times 2 = 2$.
    *   결과가 $M$ 이상($2 \ge 8$): 아니므로, XOR 연산은 생략.
    *   따라서 $d_3 = 2$.

3.  **$d_4$ 생성 (from $d_3=2$)**:
    *   이전 숫자 2배: $2 \times 2 = 4$.
    *   결과가 $M$ 이상($4 \ge 8$): 아니므로, XOR 연산은 생략.
    *   따라서 $d_4 = 4$.

4.  **$d_5$ 생성 (from $d_4=4$)**:
    *   이전 숫자 2배: $4 \times 2 = 8$.
    *   결과가 $M$ 이상($8 \ge 8$): $8 - 8 = 0$ (이진수 `000`).
    *   결과와 $k$를 XOR: $0 \oplus 3$ (`000` $\oplus$ `011`) $= 3$ (이진수 `011`).
    *   따라서 $d_5 = 3$.

생성된 시퀀스는 $5, 1, 2, 4, 3$ 입니다.

**강의 맥락**
교수님은 이 슬라이드에서 `Pseudo-Random Proving` (가상 무작위 탐색)의 한 방법으로 Shift-Register Sequence를 설명합니다. 이 방법은 이전에 논의된 `Linear Proving`이나 `Quadratic Proving`의 `Primary Clustering` 및 `Secondary Clustering` 문제를 해결하기 위해 도입됩니다. 순수하게 무작위로 탐색 위치를 정하면 나중에 해당 원소를 찾을 수 없는 문제가 발생하지만, Shift-Register Sequence는 "무작위처럼 보이지만 특정 규칙에 따라 생성된" (pseudo-random) 순열을 사용함으로써 이 문제를 극복합니다. 즉, 삽입, 삭제, 검색 시 항상 동일한 순열을 재현하여 원소의 위치를 추적할 수 있도록 합니다. 교수님은 $M=8$, $k=3$, $d_1=5$ 예시를 통해 숫자가 어떻게 생성되는지 직접 시연하며 비트 연산(`XOR`)의 원리도 설명했습니다. 이 알고리즘은 $1$부터 $M-1$까지의 숫자의 순열을 생성합니다.

**시험 포인트**
*   ⭐ **Shift-Register Sequence의 목적**: `Clustering` 문제(특히 `Secondary Clustering`)를 피하면서도 `Open Addressing`에서 예측 가능한 탐색 시퀀스를 생성하는 것입니다. 이를 통해 `O(1)`의 평균 시간 복잡도를 유지하면서 최악의 경우를 완화하려 합니다.
*   ⭐ **Shift-Register Sequence의 작동 방식**: $M$이 2의 거듭제곱이고, 특정 $k$ 값에 따라 이전 숫자를 2배하고 $M$을 뺀 후 $k$와 XOR하는 조건부 로직을 이해하는 것이 중요합니다.
*   ⭐ **Shift-Register Sequence의 한계**: 교수님은 "every value of $k$ will produce a permutation of $1$ to $M-1$ in this algorithm. However, for a given $M$, for a certain $M$, there are some $k$ that works. So it doesn't always work to have this random value of $k$ for any of the given $M$"라고 언급하며, 모든 $k$ 값이 항상 유효한 순열을 생성하지는 않는다는 점을 강조했습니다.

**핵심 개념**
*   **Shift-Register Sequence (순환 이동 레지스터 수열)**: 해시 충돌 발생 시 다음 탐색 위치를 결정하기 위한 유사 난수(pseudo-random) 프로빙(proving) 시퀀스를 생성하는 한 방법입니다. 이는 `M-1`까지의 정수들의 순열을 생성하여 탐색 위치가 고정된 패턴에 갇히지 않도록 하면서도, 일관된 규칙을 통해 나중에 검색할 수 있도록 합니다.
*   **XOR 연산($\oplus$)**: 두 비트가 같으면 0, 다르면 1을 반환하는 비트 단위 논리 연산입니다.

**코드/수식 해설**

Shift-Register Sequence 알고리즘:
1.  현재 값 $d_i$를 2배 합니다 (Shift/Double).
2.  결과가 해시 테이블 크기 $M$ 이상이면, $M$을 뺀 후 비트 단위 XOR 연산으로 1을 제거하는 것과 동일하게 처리합니다 ($d_i \leftarrow d_i \times 2 - M$).
3.  결과에 상수 $k$와 비트 단위 XOR 연산($\oplus$)을 적용합니다 ($d_i \leftarrow d_i \oplus k$).
4.  이 과정을 반복하여 $d_1, d_2, d_3, \dots$ 순열을 생성합니다.

**구체적 예시**
$M = 8$, $k = 3$으로 설정하고, 시작 값 $d_1 = 5$ (이진수로 $101$)인 경우:

1.  **$d_1 = 5$ (101)**
    *   Shift (Double): $5 \times 2 = 10$ ($1010_2$)
    *   $10 \ge M (8)$이므로 $M$을 뺍니다: $10 - 8 = 2$ ($010_2$)
    *   $\oplus 3$ (011): $2 \oplus 3 = 1$ ($010_2 \oplus 011_2 = 001_2$)
    *   $\rightarrow d_2 = 1$ ($001_2$)

2.  **$d_2 = 1$ (001)**
    *   Shift (Double): $1 \times 2 = 2$ ($010_2$)
    *   $2 < M (8)$이므로 추가 연산 없음.
    *   $\rightarrow d_3 = 2$ ($010_2$)

3.  **$d_3 = 2$ (010)**
    *   Shift (Double): $2 \times 2 = 4$ ($100_2$)
    *   $4 < M (8)$이므로 추가 연산 없음.
    *   $\rightarrow d_4 = 4$ ($100_2$)

4.  **$d_4 = 4$ (100)**
    *   Shift (Double): $4 \times 2 = 8$ ($1000_2$)
    *   $8 \ge M (8)$이므로 $M$을 뺍니다: $8 - 8 = 0$ ($000_2$)
    *   $\oplus 3$ (011): $0 \oplus 3 = 3$ ($000_2 \oplus 011_2 = 011_2$)
    *   $\rightarrow d_5 = 3$ ($011_2$)

생성된 순열은 $5, 1, 2, 4, 3$ 입니다.

**강의 맥락**
교수님은 유사 난수 프로빙(pseudo-random proving) 방법을 설명하며, 해시 충돌 시 탐색 순서를 무작위로 섞되, 나중에 검색 가능하도록 고정된 규칙을 따르는 "Shift-Register Sequence" 기법을 소개합니다. 이 방법은 $1$부터 $M-1$까지의 정수 순열을 생성하여 클러스터링을 피하려는 목적을 가집니다. 교수님은 슬라이드에 제시된 $M=8, k=3$ 예시를 따라 $d_1=5$에서 시작하여 각 단계를 상세히 설명하며 $d_2, d_3, d_4, d_5$가 어떻게 계산되는지 보여줍니다. 특히, XOR 연산의 정의(두 비트가 같으면 0, 다르면 1)를 설명한 후 예시에 적용하여 결과를 도출합니다.

**시험 포인트**
*   ⭐**Shift-Register Sequence의 목적**: 해시 테이블의 2차 클러스터링(secondary clustering)을 피하기 위한 유사 난수 프로빙(pseudo-random probing) 방법을 이해해야 합니다. 순수 난수와 달리 검색 가능하도록 규칙을 가진다는 점이 중요합니다.
*   ⭐**알고리즘 단계**: Shift-Register Sequence의 각 단계(2배, $M$ 초과 시 $M$ 빼기, $k$와 XOR 연산)를 정확히 이해하고 적용할 수 있어야 합니다.
*   ⭐**XOR 연산($\oplus$)**: XOR 연산의 정의를 알고, 이진수 계산에 적용할 수 있어야 합니다.
*   ⭐**`k` 값의 제약**: "주어진 $M$에 대해 모든 $k$ 값이 순열을 생성하는 것은 아니다"라는 Note의 의미를 인지해야 합니다. 즉, 특정 `k` 값만이 올바른 순열을 생성합니다.

## Quadratic Probing

**핵심 개념**:
Quadratic Probing은 해시 충돌을 처리하는 Open Addressing 기법 중 하나로, 다음 탐사(probe)할 위치를 찾을 때 이차 함수를 사용합니다. 이는 Linear Probing에서 발생하는 Primary Clustering 문제를 완화하기 위해 고안되었습니다. 탐사 함수 $p(i)$가 이차 형태로 정의되어, 선형 탐사보다 탐사 경로를 더 복잡하게 만듭니다.

**코드/수식 해설**:
$i$-번째 탐사 슬롯 $h_i(x)$는 다음과 같이 계산됩니다:

$$h_i(x) = (h(x) + p(i)) \mod M$$

여기서 $h(x)$는 원본 키 $x$에 대한 초기 해시 함수 출력 값(home position)입니다. $M$은 해시 테이블의 크기입니다.
탐사 함수 $p(i)$는 이차식으로 정의됩니다:

$$p(i) = c_1i^2 + c_2i + c_3$$

가장 간단한 형태의 Quadratic Probing은 $c_1=1$, $c_2=0$, $c_3=0$으로 설정하여 다음과 같이 표현됩니다:

$$h_i(x) = (h(x) + i^2) \mod M$$

여기서 $i$는 충돌이 발생한 후 탐사를 시도하는 횟수를 나타내며, $0$부터 시작합니다.
*   $i=0$: $h_0(x) = (h(x) + 0) \mod M = h(x)$ (첫 번째 시도, 원본 home position)
*   $i=1$: $h_1(x) = (h(x) + 1^2) \mod M = (h(x) + 1) \mod M$ (두 번째 시도)
*   $i=2$: $h_2(x) = (h(x) + 2^2) \mod M = (h(x) + 4) \mod M$ (세 번째 시도)
...

**강의 맥락**:
교수님은 앞서 pseudo-random probing을 설명한 후, primary clustering 문제를 피하기 위한 또 다른 방법으로 Quadratic Probing을 소개하셨습니다. `p(i)`를 $c_1i^2 + c_2i + c_3$와 같은 이차식 형태로 정의함으로써, 탐사 시퀀스를 선형 탐사($C \cdot i$)보다 더 복잡하게 만들 수 있다고 설명합니다. 이를 통해 primary clustering 문제를 어느 정도 완화할 수 있지만, 여전히 **Secondary Clustering** 문제가 발생할 수 있다고 강조하셨습니다. Secondary Clustering은 서로 다른 키라도 초기 해시 위치($h(x)$)가 같다면, 그 이후의 탐사 시퀀스가 항상 동일해지는 문제를 의미합니다.

**시험 포인트**:
*   ⭐ **Quadratic Probing의 정의 및 수식**: $h_i(x) = (h(x) + p(i)) \mod M$ 이고 $p(i)$가 이차식 형태임을 이해해야 합니다.
*   ⭐ **Quadratic Probing의 목적**: Linear Probing의 Primary Clustering을 완화하는 것입니다.
*   ⭐ **Quadratic Probing의 한계**: Secondary Clustering 문제를 해결하지 못합니다. (초기 해시 위치가 같으면 탐사 시퀀스도 같음)

## Slide 50

### 핵심 개념

해싱에서 **보조 군집화(Secondary Clustering)**는 해시 충돌을 처리하기 위해 탐사(probing) 방식을 사용할 때 발생하는 또 다른 군집화 현상입니다. **일차 군집화(Primary Clustering)**는 선형 탐사(linear probing)와 같이 순차적으로 인접한 슬롯을 탐사할 때 발생하며, 이는 유사한 초기 해시 값을 가진 항목들이 해시 테이블 내에서 연속된 위치에 삽입되어 긴 탐사 경로를 형성하는 문제입니다. 의사 난수 탐사(pseudo-random probing)나 이차 탐사(quadratic probing)를 사용하면 일차 군집화를 피할 수 있습니다.

하지만, 보조 군집화는 두 개의 서로 다른 키가 동일한 초기 해시 위치(home position)로 해시될 경우, 이 두 키는 항상 동일한 탐사 시퀀스(probe sequence)를 따르게 되는 문제입니다. 이는 탐사 시퀀스가 원래 키 값($x$)이 아니라, 전적으로 초기 해시 위치($h(x)$)와 탐사 횟수($i$)에만 의존하여 결정되기 때문에 발생합니다. 결과적으로 충돌이 발생했을 때 같은 탐사 시퀀스를 따르면서 해시 테이블의 특정 위치에 또 다른 군집이 형성될 가능성이 높아집니다.

### 강의 맥락

교수님은 앞서 배운 선형 탐사(linear probing)의 문제점인 일차 군집화를 해결하기 위해 의사 난수 탐사(pseudo-random probing)와 이차 탐사(quadratic probing)를 소개했지만, 이 방법들로도 완전히 해결되지 않는 문제가 있음을 강조하셨습니다.

"의사 난수 탐사나 이차 탐사를 사용하더라도 여전히 군집이 남을 수 있으며, 이것이 바로 **보조 군집화(secondary clustering)**라고 불립니다."라고 언급하며 보조 군집화의 개념을 도입하셨습니다.

이어 교수님은 "보조 군집화 문제는 두 키가 같은 홈 위치($h(x)$)로 해시되면, 이들은 항상 동일한 탐사 시퀀스를 따르게 된다는 것입니다. 왜 그럴까요? 그 이유는 탐사 시퀀스가 홈 위치에 전적으로 의존하며, **원래 키 값($x$)에는 의존하지 않기 때문**입니다."라고 설명하며 보조 군집화의 근본적인 원인을 명확히 짚어주셨습니다. 즉, 탐사 함수 $P(i)$가 오직 탐사 횟수 $i$에 의해서만 결정되고, `h_i(x) = (h(x) + P(i)) \pmod m`에서 $P(i)$가 $x$에 독립적이기에 초기 해시 값($h(x)$)이 같으면 탐사 경로도 같다는 것입니다.

이러한 보조 군집화는 결국 해시 테이블 내 특정 위치에 데이터가 몰리게 하여 성능 저하를 초래합니다. 교수님은 이러한 문제를 해결하기 위한 방안으로 다음 슬라이드에서 **이중 해싱(Double Hashing)**을 소개할 것임을 암시하며 마무리하셨습니다.

### 시험 포인트

*   ⭐ **보조 군집화의 정의**: 두 개의 키가 동일한 초기 해시 위치($h(x)$)로 해시될 때, 이들이 항상 동일한 탐사 시퀀스를 따르게 되는 현상을 설명할 수 있어야 합니다.
*   ⭐ **보조 군집화의 원인**: 탐사 시퀀스($P(i)$)가 원래 키 값($x$)이 아닌, 초기 해시 위치($h(x)$)에만 의존하여 결정되기 때문임을 이해해야 합니다.
*   ⭐ **일차 군집화와의 차이점 및 관계**: 일차 군집화는 선형 탐사에서 인접 슬롯 탐사로 인해 발생하고, 보조 군집화는 의사 난수 탐사나 이차 탐사에서도 초기 해시 위치가 같으면 탐사 시퀀스가 같아 발생하는 것임을 구별할 수 있어야 합니다.

## Slide 51

**핵심 개념**
더블 해싱(Double Hashing)은 해시 충돌을 처리하는 개방 주소법(Open Addressing)의 한 형태로, 특히 **2차 클러스터링(Secondary Clustering)** 문제를 해결하기 위해 고안되었습니다. 2차 클러스터링은 서로 다른 키이지만 초기 해시 함수에 의해 같은 홈 위치(home position)로 매핑된 항목들이 항상 동일한 탐사 시퀀스(proving sequence)를 따르는 현상을 말합니다. 더블 해싱은 탐사 함수를 정의할 때 두 번째 독립적인 해시 함수를 사용하여 이 문제를 완화합니다.

**코드/수식 해설**
더블 해싱에서 새로운 위치를 결정하는 탐사 함수 $p(i)$는 다음과 같이 정의됩니다.

$$
p(i) = i \times h_2(x)
$$

여기서:
- $i$: 탐사 시도 횟수($0, 1, 2, \dots$)입니다.
- $h_2(x)$: 두 번째 해시 함수로, 입력 키 $x$를 사용하여 고유한 간격 값(step size)을 계산합니다.
- 최종 해시 테이블 인덱스는 $h(x) + p(i) \pmod M$ 형태로 사용됩니다. ($M$은 해시 테이블 크기)

⭐ **시험 포인트**: $h_2(x)$는 첫 번째 해시 함수 $h(x)$와는 다른 또 하나의 해시 함수이며, **원본 키 $x$**를 인자로 받아 탐사 간격(step size)을 결정합니다. 이는 선형 탐사나 2차 탐사에서 탐사 간격이 고정되거나 초기 해시 값에만 의존하던 것과 차별화됩니다.

**구체적 예시**
키 $K_1$과 $K_2$가 있다고 가정해 봅시다.
- $h(K_1) = \text{slot A}$
- $h(K_2) = \text{slot A}$ (초기 해시 충돌 발생)

선형 탐사나 2차 탐사에서는 $K_1$과 $K_2$가 `slot A` 이후 동일한 탐사 시퀀스를 따르게 됩니다.
하지만 더블 해싱에서는:
- $p_1(i) = i \times h_2(K_1)$
- $p_2(i) = i \times h_2(K_2)$

만약 $h_2(K_1) \neq h_2(K_2)$라면, 비록 초기 홈 위치는 같더라도 $K_1$과 $K_2$는 서로 다른 탐사 간격을 가지고 해시 테이블을 탐색하게 됩니다. 이로써 2차 클러스터링을 피할 수 있습니다.

**강의 맥락**
교수님께서는 2차 클러스터링 문제를 "두 개의 키가 동일한 홈 위치(home position)로 해시되면, 이들이 항상 동일한 탐사 시퀀스를 따라가게 되는 문제"라고 설명하며, 이는 기존의 선형 탐사(linear probing), 2차 탐사(quadratic probing), 유사 난수 탐사(pseudo-random probing) 방식에서 발생하는 문제라고 강조하셨습니다. 이러한 방식에서는 탐사 시퀀스가 주로 홈 위치와 탐사 횟수에만 의존하여, 아무리 복잡한 탐사 함수를 사용하더라도 초기 위치가 같으면 탐사 패턴도 같아진다고 하셨습니다.

이 문제의 근본적인 원인은 "탐사 시퀀스가 전적으로 홈 위치(home position)와 원본 키(original key value)의 함수에 의존"하고, 특히 탐사 함수가 키의 원래 값을 활용하지 못하기 때문이라고 지적하셨습니다. 이를 해결하기 위해 교수님께서는 **더블 해싱**을 도입하셨습니다. 더블 해싱의 핵심 아이디어는 "탐사 함수 $p(i)$를 두 번째 해시 함수 $h_2$를 사용하여 정의하는 것"이라고 설명하셨습니다. $h_2$는 원본 키 $x$를 입력으로 받아 탐사 간격을 결정하므로, 설령 두 키의 첫 번째 해시 값($h(x)$)이 같더라도 $h_2(x)$ 값이 다르다면 서로 다른 탐사 시퀀스를 갖게 되어 2차 클러스터링 문제를 회피할 수 있다고 강조하셨습니다.

⭐ **시험 포인트**: 더블 해싱의 핵심은 **두 번째 해시 함수 $h_2(x)$가 원본 키 $x$를 사용하여 탐사 간격을 결정**한다는 점입니다. 이는 1차, 2차, 유사 난수 탐사가 해결하지 못하는 2차 클러스터링 문제를 해결하는 중요한 메커니즘입니다.

## Slide 52

**핵심 개념**: 해시 테이블은 평균적으로 $O(1)$ 탐색 시간을 제공하지만, 최악의 경우($O(N)$) 발생 가능성, 실시간 시스템 부적합성, 그리고 악의적인 공격에 대한 취약점 등 내재된 문제점들이 존재한다.

**구체적 예시**:
*   **실시간 시스템**: 항공 관제 시스템과 같이 예측 가능한, 일정한 응답 시간이 필수적인 시스템에는 해시 테이블의 최악의 경우 성능($O(N)$)이 치명적인 위험을 초래할 수 있다.
*   **악의적인 공격 (해시 플러딩)**: 공격자가 해시 함수의 특성을 파악하여 의도적으로 모든 키가 동일한 해시 버킷으로 매핑되도록 만들면, 해시 테이블의 성능을 $O(N)$으로 저하시켜 서비스 거부(DoS) 공격을 유발할 수 있다. 이는 과거에 실제로 많이 발생했던 문제이다.

**강의 맥락**:
교수님은 해시 테이블이 평균적으로 $O(1)$의 빠른 탐색 속도를 자랑하지만, "평균"이라는 단어 뒤에 숨겨진 문제점들을 퀴즈를 통해 강조한다.

1.  **최악의 경우 탐색 비용은 얼마이며, 언제 발생하는가?**
    *   ⭐ **답변**: 최악의 경우 탐색 비용은 $O(N)$이다. 이는 모든 입력 키가 동일한 해시 함수 출력 값을 가지게 되어 모든 요소가 하나의 슬롯(또는 체인)에 충돌하는 상황에서 발생한다. 즉, 해시 테이블의 모든 요소가 연결 리스트처럼 한 줄로 늘어서는 경우이다.
2.  **해시 테이블이 실시간 시스템(예: 항공 관제)에 부적합한 이유는 무엇인가?**
    *   ⭐ **답변**: 실시간 시스템은 예측 가능하고 일관된 응답 시간을 요구한다. 해시 테이블은 평균적으로 빠르지만, 최악의 경우 $O(N)$이라는 예측 불가능한 지연이 발생할 수 있으므로, 안전이 중요한 실시간 시스템에는 재앙이 될 수 있어 사용해서는 안 된다.
3.  **만약 공격자가 키를 선택할 수 있다면, $O(1)$ 성능을 $O(N)$으로 만들 수 있는가?**
    *   ⭐ **답변**: 가능하다. 공격자는 해시 함수의 동작 방식을 예측하거나 심지어 해시 함수 코드를 확보하여, 의도적으로 많은 키들이 동일한 해시 버킷으로 매핑되도록 조작할 수 있다. 이로 인해 대량의 충돌이 발생하면 해시 테이블의 탐색 시간이 $O(N)$으로 늘어나 시스템 성능을 마비시키는 서비스 거부(DoS) 공격(특히 "해시 플러딩")을 일으킬 수 있다. 현재는 해시 함수를 무작위화하고 여러 해시 함수를 사용하는 등의 방법으로 이러한 문제를 완화하려 노력하고 있다.

## Slide 53

## Summary

이 슬라이드는 해시 테이블 관련 강의의 핵심 개념을 요약합니다.

### 핵심 개념

*   **Dictionary (사전)**
    *   키(key)와 정보(information) 쌍으로 이루어진 추상 자료형(ADT)입니다. 각 키는 고유하며, 해당 키와 연관된 단일 항목을 가집니다.
    *   기본 연산은 삽입(Insert), 삭제(Delete), 검색(Search)입니다.
    *   구현 방법으로는 정렬/비정렬 리스트, 이진 탐색 트리, 균형 이진 탐색 트리, 해시 테이블 등이 있습니다.
*   **Hash Function (해시 함수)**
    *   키를 입력받아 해시 테이블 내의 해당 인덱스(슬롯 주소)를 출력하는 함수입니다. 이 과정은 매우 빠르게 $O(1)$ 시간 복잡도로 수행되어야 합니다.
    *   이상적인 해시 함수는 충돌을 최소화하고 키를 해시 테이블 슬롯에 균일하게 분배합니다.
    *   주어진 키를 정수 값으로 변환한 다음, $0$에서 $m-1$ 범위의 슬롯 주소로 매핑하는 두 단계를 거칩니다.
    *   ⭐**Division Method**: `h(x) = x mod m`을 사용합니다.
        *   $m$은 소수(prime number)이거나 홀수(odd number)를 사용하는 것이 좋습니다. 이는 입력 키의 특정 패턴(예: 짝수/홀수 편향, 특정 숫자의 배수)으로 인한 해시 충돌 편향을 줄이는 데 도움이 됩니다. $m$값이 클수록 충돌 가능성이 낮아집니다.
    *   ⭐**Mid-Square Method**: 키를 제곱한 후 결과 값의 중간 비트(digit)를 추출하여 해시 값으로 사용합니다. 키의 모든 자릿수가 해시 값에 영향을 미치도록 하여 균일성을 높입니다.
*   **Hash Table (해시 테이블)**
    *   키-정보 쌍을 저장하는 자료구조입니다. 각 항목이 저장되는 개별 단위를 '슬롯(slot)' 또는 '버킷(bucket)'이라고 부릅니다.
    *   ⭐**설계 시 상충하는 목표**: 해시 테이블 크기를 작게 유지(압축성)하면서도 충돌 발생 횟수를 최소화해야 합니다.
    *   주요 고려 사항: 해시 함수 선택, 충돌 처리 방식, 해시 테이블 크기 설정, 오버플로우 처리 등입니다.
*   **Collision (충돌)**
    *   서로 다른 두 개 이상의 키가 동일한 해시 테이블 슬롯으로 매핑되는 현상입니다.
    *   키를 해시 테이블 크기로 압축하는 과정에서 필연적으로 발생할 수 있으며, 효율적인 처리가 필수적입니다.
*   **Open Addressing (선형 / 이차 탐사)**
    *   충돌 처리 방법 중 하나로, 모든 요소를 해시 테이블 내에 직접 저장합니다 (추가적인 연결 리스트 등을 사용하지 않음).
    *   각 슬롯은 '비어있음(empty)', '점유됨(occupied)', '삭제됨(deleted)'의 상태를 가집니다.
    *   ⭐**Probing (탐사)**: 충돌 발생 시, 다른 빈 슬롯을 찾아 이동하는 과정입니다. 탐사 함수 `p(i)`를 사용하여 다음 탐사할 위치를 결정합니다.
        *   $$h_i(x) = (h(x) + p(i)) \pmod m$$
        *   `h(x)`는 최초 해시 함수 값, `i`는 탐사 횟수, `m`은 해시 테이블 크기입니다.
    *   **Linear Probing (선형 탐사)**: `p(i) = i`. 충돌 시 바로 다음 슬롯을 순차적으로 탐사합니다.
        *   ⭐**Primary Clustering (주 클러스터링)**: 유사한 해시 값을 가진 항목들이 해시 테이블 내에 연속적인 블록을 형성하여, 탐사 길이가 길어지는 문제입니다.
    *   **Quadratic Probing (이차 탐사)**: `p(i) = c_1 i^2 + c_2 i + c_3` (이차식 형태). 충돌 시 2차 함수에 따라 떨어진 위치를 탐사합니다. 주 클러스터링 문제를 완화하는 데 도움이 됩니다.
*   **Separate Chaining (분리 연결법)**
    *   충돌 처리 방법 중 하나로, 'Open Hashing'이라고도 불립니다.
    *   충돌이 발생하면, 해당 해시 테이블 슬롯에 연결 리스트(linked list)를 생성하여 충돌한 모든 항목들을 저장합니다.
    *   모든 데이터를 주 메모리(main memory)에 유지할 수 있을 때 적합하며, 포인터 연산에 용이합니다.
*   **Load Factor (적재율)**
    *   해시 테이블에 저장된 항목 수와 해시 테이블 크기의 비율입니다. 적재율이 높을수록 해시 충돌이 증가하고 성능이 저하될 가능성이 큽니다. (강의 음성에서는 직접적인 정의 없이 중요성만 간접적으로 언급됨)
*   **Rehashing (재해싱)**
    *   강의 맥락에서 'Rehashing'은 주로 오버플로우 버킷 없이 해시 테이블 내에서 직접 탐사(Open Addressing)를 통해 충돌을 처리하는 방식을 지칭합니다.
    *   (일반적인 의미에서 재해싱은 해시 테이블의 적재율이 너무 높아졌을 때, 더 큰 해시 테이블을 만들고 모든 기존 항목을 새 해시 함수를 사용하여 재배치하는 과정을 의미하기도 합니다.)
*   **Clustering (클러스터링 - 주 / 보조)**
    *   **Primary Clustering (주 클러스터링)**: 선형 탐사에서 발생합니다. 초기 해시 값이 비슷한 키들이 해시 테이블의 특정 영역에 집중되어 긴 탐사 경로를 형성하는 문제입니다.
    *   ⭐**Secondary Clustering (보조 클러스터링)**: 이차 탐사나 유사-무작위(pseudo-random) 탐사에서 발생합니다. 두 키의 **초기 해시 위치가 동일하면**, 이후의 **탐사 시퀀스 또한 항상 동일**하게 됩니다.
        *   이를 해결하기 위해 **Double Hashing (이중 해싱)** 방식이 사용됩니다. `p(i) = i * h_2(x)`와 같이 두 번째 해시 함수 `h_2(x)`를 사용하여 탐사 간격(step size)을 결정함으로써, 초기 해시 값이 같더라도 키 자체에 따라 다른 탐사 시퀀스를 가지도록 합니다.
*   **Average $O(1)$ Search / Insert / Delete (평균 $O(1)$ 검색/삽입/삭제)**
    *   해시 테이블의 가장 큰 장점으로, 적절한 해시 함수와 충돌 처리 방법을 사용하면 삽입, 삭제, 검색 작업이 평균적으로 상수 시간 ($O(1)$) 내에 완료됩니다.
    *   이는 데이터베이스 크기 $N$에 비례하여 시간이 증가하지 않는 "마법과 같은" 성능입니다.
    *   ⭐**최악의 경우 ($O(N)$)**: 모든 키가 동일한 해시 슬롯으로 매핑될 때 발생합니다. 이 경우 검색이 선형 탐색으로 퇴화됩니다.
    *   ⭐**실시간 시스템에 부적합**: 최악의 경우 $O(N)$ 성능 때문에, 비행 관제와 같이 항상 $O(1)$ 성능이 보장되어야 하는 실시간 시스템에는 해시 테이블이 적합하지 않습니다.
    *   ⭐**보안 취약점 (DoS 공격)**: 공격자가 해시 함수를 유추하여 모든 키가 동일한 슬롯으로 매핑되도록 의도적인 입력을 보낼 경우, 해시 테이블을 $O(N)$ 성능으로 만들어 서비스 거부(DoS) 공격(예: 해시 플러딩)을 유발할 수 있습니다.
